# 其它栏目八股评审

对照 3 年 Go 社招一面，看了 `Guide/content/其它/其它` 下全部中文正文（`_index.md`、1.hr、2.AI、3.Linux、4.vpn、5.跨域、6.限流、7.场景题）。`en.md` 只扫了和中文是否打架，不当主审对象。

Linux 的 rwx / Shebang、free 里先看 available、`x/time/rate` 惰性补令牌、排查章的「范围 → 止血 → 链路」，这几块能讲。问题集中在跨域把拦截说死、滑动窗口三套时间对不上，以及场景题 1 几乎只有题干。

## 结论

先改这三处，面试里不能照背：

1. 跨域时浏览器把请求拦住，同时又说后端一定收到了
2. 任意 1 秒窗口拆成 6 格、每格 10ms
3. 令牌桶的流出速率是动态可变的

## 面试高频但几乎没写的

覆盖 rwx、free/available、固定窗口突刺、令牌桶惰性计算、超时排查四段，正文里已经有。缺的是这些能接上现有章节的一面题。

### 5.跨域 — 有同源，缺预检

协议 / Host / 端口不同就是跨域，这句够开场。一面真正卡人的是：这次请求后端收没收到、JSON POST 会不会先 OPTIONS、为什么 form 能跨域递数据。

现在后文给了一句「一定收到」，和开场「拦住」对着干。补简单请求 / 预检，这两句才能收口。JSONP 一句带过即可，不要展开。

### 6.限流 — 有单机算法，缺多实例

四种算法和 `x/time/rate` 的小数令牌，作为口述主链够用。缺的是：两个 Go 进程各有一个 Limiter 时，限额是加出来的。

接在现有对比表后面一句：网关或 Redis 做集群上限，进程内桶做自保。熔断、降级不要写成限流的一种。

### 7.场景题1 — 只有题干

库存超卖、热点 key、点赞写扩散、UV、幂等，都是 3 年 Go 一面的常规题。现在只记了背景和主问。

每题留 4 到 6 句主路径就能复习。细节（分库、推荐特征、排行榜算法）不要在这一栏堆成系统课。分布式锁正文在 `其它/运维/4.分布式`，本栏库存 / 热点题要能指过去，不要在这里重写一整章。

### 3.Linux — 有 top/free，缺 load 和收尸

## 三处建议改口

### 跨域时后端收没收到

现在：请求发出去了，后端也收到了，浏览器把数据扣下。

更好：先问是不是预检。普通 GET/表单 POST 会到后端，浏览器不把响应交给 JS。带 JSON 或自定义头会先 OPTIONS，预检不过就没有第二次请求。不要先说「拦住」，也不要先说「一定收到」。

### 令牌桶和漏桶

现在：令牌桶流出速率动态可变；漏桶固定。

更好：两个都有平均速率 r。漏桶匀速漏，桶满则拒绝或排队，空闲也加速不了。令牌桶按 r 生令牌，桶里有存货就可以突发，突发上限是 burst。`x/time/rate` 的 `burst` 就是这个上限。

### 滑动窗口怎么数格子

现在：1 秒限额，6 格每格 10ms。

更好：滑动计数是把窗口切成 n 个小格，求和近似真实滑动。格子越细越准、key 越大。口里要能算：窗口 ÷ 格宽 = 格数。精确到每笔请求再用 ZSET 滑动日志。
