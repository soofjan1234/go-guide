# Agent 八股评审

对照 2025–2026 的 Transformer / 工具调用 / MCP / 上下文工程常识，看了 `Guide/content/其它/Agent` 下 `_index.md` 和 1–9 主要正文（含 `5.框架开发` 的 `index.md`、`index2–5.md`）。`pic/` 只扫了文字说明，不当成主章节。

四件套、ReAct 循环、Tool / Skill / MCP 对照、create_agent 工具环、客服分流和失败分类，这几块整体能讲。问题集中在把论文名写错、把过时产品限制当现状，以及注意力 / KV cache / 原生 Function Calling 几乎没接到工程追问。

本文件只评 Agent 栏。Lang-Agent 栏更细（存历史和本轮投喂分开、裁剪要保住 ToolMessage 成对），和本栏第 6、7 章力度不同；不要把两边合成一份笔记。

## 结论

先改这两处，面试里不能照背：

1. 范式标题写成 `Plain and Solve`，正文又把 Plan-and-Solve 提示词论文讲成现在的 Agent 模式
2. Coze「不支持 MCP」

顺手改开场这两句，追问时也容易穿：Transformer「一次看完全文」，以及 XML 标签能避免 Prompt Injection。

## 面试高频但几乎没写的

幻觉原因和四层防线、权限确认、失败按类型处理，第 1、9 章已经有。缺的是能接上第 2、4、8 章的工程追问。

### 2.语言模型 — 有 Q/K/V 故事，缺公式和 KV cache

自注意力比喻能讲。一面更常默写公式、问为什么除 √dₖ、问生成为什么越来越快。

补最短三句：公式、因果掩码、KV cache（prefill / decode）。位置编码从绝对 PE 接到 RoPE。不要把 Encoder「一次看全文」说成 GPT 的生成方式。

### 4.范式 / 8.协议 — ReAct 和 Tool Calling 没对上

ReAct 循环和第 8 章的天气例子其实是两条线。现在问 Agent 怎么调工具，标准答案是：模型出结构化调用，运行时执行，结果当 Observation 回填。ReAct 是早期提示词格式，格式脆弱、token 多。

MCP 不要停在「连 Server」。Host / Client / Server 分清后，再加一句 A2A 管 Agent 之间，MCP 管工具和资源。

### Prompt Injection — 只出现在「打 XML 标签」

第 7 章把注入收成标签隔离，等于没写治理。该补的是：检索和工具输出当不可信数据、工具鉴权、副作用确认。第 1 章的人工确认可以接到这里，不必新开一章。

### 评测和成本 — 有 RAG 分数，缺 Agent 账本

第 6 章 RAGAS 四项够用半页。缺任务成功率、工具是否选对、轮次、输入/输出 token、TTFT。输出 token 和解码步数通常比「把资料全塞进窗口」更贵；这和 KV cache、第 7 章的压缩是同一条链。

## 三处建议改口

### Transformer 开场

现在：与其一个词一个词地读，不如把整段文本同时摊开，让模型一次看到所有位置。

更好：训练时可以对序列并行算注意力，不再等 RNN 的上一步。Encoder 双向；Decoder 有因果掩码，生成时只看已经出现的前缀。每个新 token 用 KV cache 接在后面，不必重算整段历史。

### ReAct 第一句

现在：思考与行动相辅相成，Thought → Action → Observation 大循环。

更好：这是早期用提示词把推理和行动写在同一段文本里。现在常用原生 Function Calling：模型只出工具名和参数，程序执行后再把结果塞回消息列表。循环还在，格式约束从「模型必须打对 Action:」换成了 schema。

### MCP 是什么

现在：Agent 连接 MCP Server，发现并使用能力。

更好：Host 是应用，Client 是 Host 里连一台 Server 的那一端，Server 提供工具、资源和提示词。模型仍然只做 Tool Calling；谁允许调、调完要不要问人，是 Host 的事。

## 写得比较稳的部分

`1.基础` 的模型 / 规划 / 记忆 / 工具，以及幻觉四层（输入 RAG、过程校验、输出 Guardrail、高风险确认），口述主链够用。`3.交互和分词` 的 Temperature / Top-k / Top-p 顺序，和 strawberry 分词例子，能讲清「模型读的是 Token」。`6.记忆` 把 RAG 写成桥而不是记忆本身，和窗口、情景、语义的分层是对的。`8.通信协议` 的 Tool Calling 四步（注册 → 决策 → 程序执行 → 回填）和 Tool / Skill / MCP 对照表可以直接背。`5.框架开发` 里 `create_agent` 的工具环、LangGraph 的 State / Node / 条件边 / `add_messages` reducer，以及 `9.设计` 的客服分流和失败分类（超时重试、缺参追问、选错工具降级、外部不可用终止），作为工程题能收住。
