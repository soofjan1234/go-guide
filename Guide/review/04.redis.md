# Redis 八股评审

对照现行 Redis 6/7（命令执行仍单线程、6 起 IO 线程、4.0 混合持久化、7.0 listpack 与多文件 AOF）看了 `Guide/content/中间件/Redis` 下全部正文，含 `_index.md` 和 1 到 6。

缓存三兄弟的方向、Cache Aside 四种推理、RDB 的 fork/COW，这几块整体能讲。问题集中在把删缓存可靠性说成强一致、把 Lua 原子范围吹成全集群，以及底层编码按 7.0 写却不标 6.x 的 ziplist。

## 结论

先改这五处，面试里不能照背：

1. MQ / Canal 删缓存写成「极致一致性」
2. Lua 绝对原子、彻底不需要分布式锁
3. 先更新库再删缓存「只是短暂读到旧数据」
4. 小数据底层一律 ListPack，不提 Redis 6 的 ziplist
5. GET 再 SET 算成 3 次 RTT

## 面试高频但几乎没写的

不是要把每章写成源码课。下面这些是 3 年 Go 社招一面里比 listpack 字节布局、Functions 更常出现的。ACL、client-side caching、Functions 知道名字即可，不必展开。

### 单线程与 IO 线程 — 现在整栏缺

面试第一句通常是：为什么单线程还快，6.0 多线程改了什么。

建议口吻：数据结构和命令执行仍是一条主线程，所以单命令原子、没有命令级锁。快是因为内存、IO 多路复用、高效编码。6 起 `io-threads` 只分担读套接字、解析、写回包；`io-threads-do-reads` 才把读也卸出去。fork 子进程做 RDB/AOF 重写，UNLINK 做惰性释放，这些更早就是后台线程，不要和 IO 线程混成「Redis 已经多线程执行命令」。

### 大 key / 热 key / 复杂度 — 现在只有一句 UNLINK 影子

一面常问：什么是大 key，为什么危险，怎么查、怎么拆。热 key 和击穿相邻但不是同一题。

建议顺序：命令复杂度（O(1) / O(log N) / O(N)）→ 禁止 KEYS、无界 HGETALL/LRANGE → 大 key 阻塞过期、淘汰、主从、集群迁移 → `UNLINK` / 拆 key → 热 key 本地缓存或分片。

### 集群槽位、主从、脚本 — 6.其他只有单机 Lua

Cluster 是 16384 槽。问到迁移要能说 `MOVED` / `ASK`，导入导出期间 key 可能临时不在本节点。Lua 和事务都要求 key 同槽，常用 hash tag `{userId}`。

主从：副本默认异步，有丢失窗口；脚本不要用随机和 `TIME` 当写入依据，5 起复制的是脚本产生的写命令，老说法「从库再跑一遍脚本」已经过时。

### 分布式锁与 Pipeline — 和 Lua 章接不上

锁：`SET key token NX EX`，解锁用 Lua 比对 token 再 `DEL`，不要只 `DEL`。一面会追问过期了业务还在跑、主从 failover 丢锁；Redlock 有争议，能说风险比背名字重要。

Pipeline：把多次命令一次性写出去，减 RTT，但中间可见、不原子。和 MULTI、Lua 的对比放在 6.其他开头，比单独吹 Lua 更完整。

## 三处建议改口

### 双写不要说极致一致

现在：消息队列或 Canal 订 Binlog，就是极致一致性。

更好：先更新数据库再删缓存，接受极短窗口的旧读。删失败就重试、丢队列或跟 Binlog，把「缓存长期脏」变成「很快会再长出来」。旧值回种仍可能发生，要强一致就别把 Redis 当真相。

### Lua 原子性第一句

现在：整个脚本绝对原子，彻底杜绝并发，不必分布式锁。

更好：这段脚本在同一个 Redis 实例上连续跑完，中间不插入别人的命令。key 必须声明且同槽；跑太久全实例停。单 key 扣库存可以直接 Lua。跨 key、跨服务仍用锁，解锁也用 Lua。

### 过期和淘汰第一句

过期：带 TTL 的 key，时间到了就该消失，惰性加定期，定期从 expires 里抽。淘汰：内存碰到 maxmemory，按策略赶人，跟 TTL 到没到不是同一件事。`volatile-lru` 只从「设过过期时间」的里面挑，不是从已过期集合里挑。

## 写得比较稳的部分

`3.缓存三兄弟` 的穿透、击穿、雪崩方向没有写反，布隆「有 0 则一定不在、全 1 只是可能在」和不能随便删 bit，能直接口述。`5.双写一致性` 里先删再写库会回种旧值、先改缓存会造成「库未承认的值」，这两条推理是对的。`2.持久化` 的 fork 后 COW、改页才复制，以及 AOF 缓冲区到 Page Cache 再 fsync，作为主链够用。`4.过期与淘汰` 的「抽 20 个、超过 1/4 继续」和 Redis 默认定期过期循环一致。`1.数据结构` 里 ZSet 大数据用 dict 加点查、skiplist 做范围，member 共享，这句可以留。
