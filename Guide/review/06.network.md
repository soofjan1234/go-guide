# 网络八股评审

对照 TCP/IP、HTTP/1.1–3、TLS 1.2/1.3、Go netpoller/epoll 常识看了 `Guide/content/其它/网络` 下 `_index.md` 和 1–9 全部正文。pic/ 下图解 md 只扫了标题文字，不逐像素对图。

三次握手 / 四次挥手状态、HTTP/2 多路复用仍可能被 TCP 连坐、gRPC 四种流、UDS 对比这几块整体能讲。问题集中在拥塞控制口诀含糊、证书公钥用途和 ECDHE 打架、以及把 Go 的 M 说成从不会被内核挂起。

## 结论

先改这五处，面试里不能照背：

1. 拥塞控制「有包丢失降到中界线、超时降到低端」
2. 证书里的公钥用来协商对称密钥
3. Go 的 M 从不真正被内核挂起
4. HTTP/2 一个 Stream 只传输一个 Message
5. NIO 把非阻塞 I/O 和 epoll 多路复用捏成一件事

| 重要 | Socket | 从网络协议视角 | 写成 Socket 由「IP + 端口 + 传输协议」唯一定位。监听套接字可以这么说；已建立的 TCP 连接是五元组，同一服务器端口上可以有很多条连接。 | 改成：监听端点是协议 + 本地 IP + 本地端口。一条 TCP 连接是五元组。不要说三元组在全网唯一。 |

## 面试高频但几乎没写的

HTTP/2 多路复用和 TCP HOL、四次挥手半关闭、gRPC 四种流、UDS vs TCP、sendfile 名字，正文里已经有。缺的是这些能接上现有章节的一面题。

### HTTPS — 有 ECDHE，缺握手

混合加密和证书链能讲。一面更常按时间线问：ClientHello 里有什么、证书公钥干什么、1.2 和 1.3 差几个 RTT、0-RTT 有什么风险。

现在证书那句还在说「公钥协商对称密钥」，和 ECDHE 打架。先改用途，再补 1.3 的 1-RTT，不要背「四次握手」当现行标准。

### HTTP — 有版本演进，缺登录态

Keep-Alive、Host、Range、HPACK 有了。Cookie / Session / JWT、以及 Keep-Alive 和 TIME_WAIT 怎么接，几乎没写。这些比 Server Push 更常出现。

### TCP — 有状态机，缺窗口和队列

握手挥手序列可以背。缺的是：发送窗口是 `min(cwnd, rwnd)`、半连接/全连接队列、FIN+ACK 合并成三次挥手。拥塞那四句先改掉再补这三句。

### IO / Go — 有 BIO/NIO/AIO，缺 epoll 和 netpoller 边界

模型分类能开场。缺 select/poll/epoll 和 LT/ET。Go 段不要说 M 永不阻塞，说清只对 socket 走 netpoller。

### DNS — 有角色，缺过程

Stub / 递归 / 权威分工是对的。补递归解析器对外迭代、A vs CNAME、TTL。CDN 调度点到为止，不要写成 DNS 专章。

## 四处建议改口

### 拥塞控制

现在：有包丢失就降到中界线继续拥塞避免；超时降到低端再慢开始。

更好：真正发出去的是 `min(cwnd, rwnd)`。慢开始指数加到 `ssthresh`，再线性加。3 个重复 ACK 说明后面还有包能到，快重传并把窗口降到大约一半；超时才回到慢开始。Linux 默认 CUBIC，口诀仍用 Reno 讲原理，不要把「中界线」当术语。

### 证书公钥干什么

现在：服务器公钥用于后续握手协商对称密钥。

更好：证书证明「你连的就是这个域名的机器」。公钥用来验证服务端对密钥交换的签名。对称密钥来自双方临时 ECDHE，不经过证书公钥加密。TLS 1.3 首次大约 1-RTT，不要只说 SSL 四次握手。

### Go 网络为什么看起来是同步的

现在：M 从不真正被内核挂起，G 丢掉给 Netpoller。

更好：socket 是非阻塞的。`Read` 没数据就 park 这个 G，M 去跑别的 G；数据来了 epoll 把 G 叫醒。文件和 cgo 仍可能堵住 M。这是同步写法 + 运行时调度，不是 AIO。

### HTTP/2 还堵不堵

现在：多路复用——解决队头阻塞。

更好：同一条连接上多路 Stream 不再按请求排队，这解的是 HTTP/1.1 的应用层阻塞。底层还是 TCP 字节流，丢一个段，其他 Stream 也要等重传。真正按流重传是 HTTP/3 / QUIC。

## 写得比较稳的部分

`4.TCP` 三次握手的 seq/ack 和「第三次 ACK 丢了、后续带 ACK 的数据包仍能把服务端拉进 ESTABLISHED」，以及半开连接靠 keepalive / 超时 / RST，能讲圆。四次挥手的半关闭、TIME_WAIT 等 2MSL 的两条理由、CLOSE_WAIT 堆起来先查没 `close`，作为口述主链够用。`2.HTTP` 后段「二进制分帧后仍可能 TCP 层 HOL」和 `2.HTTP补充` 的全双工 TCP vs HTTP 请求—响应，比很多只背「HTTP 半双工」的稿子完整。`7.RPC` 四种流和 Metadata 不放业务字段、`9.Socket` 的 UDS 六条对比、`6.NAT` 的 SNAT/DNAT 和锥型由易到难，方向是对的。
