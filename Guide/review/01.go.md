# Go 1–16 八股评审

对照现行 Go（含 1.24 Swiss Table / HashTrieMap、1.21 `panic(nil)`、1.26 Green Tea）看了 `Guide/content/Go/Go` 下 1 到 16。

GMP、channel 收发主路径、pprof 排查模型、Gin 请求链这几块整体能讲。问题集中在版本没跟上、把相邻概念说成一件事、以及切片 / Gorm 对面试不够用。

> 聊天旁那份可筛选表格是 Cursor Canvas，源文件必须放在 IDE 的 `canvases/` 目录，Hugo 站点不会读它。本文件是同一份评审的仓库副本，方便 git 和后续改正文。

## 结论

先改这五处，面试里不能照背：

1. sync.Map 还在讲 read/dirty
2. Swiss Table 写成 16 槽且 H1 能点到槽
3. `panic(nil)` 仍当 `recover` 为 nil
4. mutex profile 的采样方向说反了
5. channel 的 `qcount` 和 `dataqsiz` 混成同一个字段

## 面试高频但几乎没写的

不是要把每章写成源码课。下面这些是 3 年 Go 社招一面里比 Swiss Table 目录深度、sema 实现更常出现的。

### 2.切片 — 现在偏公式，缺使用陷阱

扩容规则可以留，但面试更常画切片头，追问 append 会不会换数组、两个切片改同一个底层、nil 和空切片打 JSON 分别是 null 和数组、截取大 buf 导致内存不掉。

建议顺序：结构 → 共享/拷贝 → nil vs empty → 扩容 → 对齐到 size class。

### 16.Gorm — 现在只有选型

对比 Gorm/Ent/sqlc/Bun 够用半页。缺的是：Updates 跳过零值、Preload N+1、事务回滚、软删除、把 ctx 传进去、连接池参数。

这些和 Gin 的 `required` 零值、Context 取消是同一类「框架会坑你」的题，现在 Gorm 章接不上。

### 3.Map / 12.竞态 — 源码和使用断开

第 3 章直接进 Swiss Table，第 12 章第一句「不是。」题目还没出现。面试通常先问并发、nil map、遍历顺序，再问你知不知道 1.24 换过实现。

使用规则放第 3 章开头，并发方案只在第 12 章展开，并写明问的是「map 并发安全吗」。

### 11.内存 — GC 缺线上开关

三色、写屏障、分配器层级已经能讲。缺 GOMEMLIMIT、GOGC、以及逃逸分析不要说成「这些写法一定上堆」。

Green Tea 在 1.26 默认开启，这句是对的；补一句对象是否存活仍看指针可达，变的是扫描组织方式。

## 三处建议改口

### Select 第一句

现在：有多个 channel 时，select 会随机选择一个 channel 进行处理。

更好：多个 case 同时就绪时，runtime 打乱检查顺序后挑一个，避免总走第一个。只有一路就绪就走那一路；都不就绪就阻塞，有 default 才立即返回。

### sync.Map 开场（1.24）

从 1.24 起内部是并发哈希树，不再靠 read 晋升 dirty。Load 沿哈希 4 位一层往下走，一般不加全局锁；写入锁的是相关节点。

适用场景官方原文还在：缓存只增，或各 goroutine 管自己的 key。写多、要事务，仍用 map+Mutex。

### Context 作用

取消、超时、请求级元数据。不要说「用来传参」。业务入参走函数参数；Value 只放 trace / 身份这类跨层元数据，key 用未导出类型。
