# 运维八股评审

对照 Docker OverlayFS、K8s 现行资源对象与调度常识、分布式 ID/锁常识，看了 `Guide/content/其它/运维` 下 `_index.md`、1.Docker（`index.md` 和 `docker/` 配图）、2.k8s（`index.md` 和架构/资源对象图）、4.分布式。目录没有第 3 章。

共享内核、自定义 bridge 用容器名、SET NX EX 两步死锁、Service 四种类型这几块能讲。问题集中在把容器说成只写、把三种探针都当成重启、以及把 Secret 的 Base64 说成加密。

## 结论

先改这四处，面试里不能照背：

1. Image 只读、Container 只写
2. Liveness / Readiness / Startup 失败都会重启容器
3. Secret 用 Base64 编码加密存储
4. 管理员改 etcd，所有节点瞬间更新配置

### 错误（说错了）

| 级别 | 章节 | 位置 | 问题 | 改法 |
| --- | --- | --- | --- | --- |
| 阻断 | 1.Docker | Image 和 Container 区别第 2 条 | 写成 Image 只读、Container 只写。容器看到的是 merged：可读可写。可写的是 upperdir，lowerdir 仍是只读镜像层。配图已经画了对的 Writable Layer，和正文打架。 | 改成：镜像层只读、可共享；每个容器加一层可写层。读优先看 upperdir，没有再看镜像层。改文件时 Copy-on-Write 拷到可写层，删文件用 whiteout 遮住，不改镜像。 |
| 阻断 | 2.k8s | kubelet 健康检查 | 点了 Liveness、Readiness、Startup，紧接着写成容器挂了就重启。Readiness 失败只是从 Service 摘掉，不重启。容器进程退出走的是 restartPolicy，也不是三条探针共用一条结论。 | 拆开：Liveness 失败 kubelet 重启容器；Readiness 失败移出 Endpoint，流量不进来；Startup 先挡住前两个，启动慢的应用用。进程崩了才看 restartPolicy，默认 Always。 |
| 阻断 | 2.k8s | ConfigMap & Secret | 写成 Secret 以 Base64 编码加密存储。etcd 里默认就是 Base64 后的明文，谁都能 decode。加密要另开 EncryptionConfiguration。 | 改成：API 里是 Base64，方便传输二进制，不是加密。权限靠 RBAC；落盘加密是可选的 etcd encryption at rest。 |
| 阻断 | 2.k8s | etcd 第 3 条 | 写成管理员在 etcd 里改配置，Watch 让所有服务器瞬间更新。不要直接改 etcd。组件 Watch 的是 API Server。只有 apiserver 读写 etcd。 | 删掉这句。改成：改资源走 kubectl / API；apiserver 写入 etcd 后，控制器和 kubelet 从 API Watch 到变化。 |
| 重要 | 1.Docker | Image 和 Container 区别第 1 条 | 写成 Container 是动态的、正在运行的。exited 的容器还在，`docker ps -a` 看得到，可写层也还在，除非删掉。 | 改成：容器是镜像的实例，状态可以是 created / running / exited。删容器才丢掉默认可写层。 |
| 重要 | 1.Docker | 为什么需要 tini 第 2 条 | 收割僵尸写成防止内存泄漏。僵尸占的是 PID 表项，不是业务内存泄漏。 | 改成：PID 1 必须 wait 子进程，否则僵尸会占满 PID。普通 Go HTTP 服务自己不 fork 的话，更常考的是信号，不是僵尸。 |
| 重要 | 1.Docker | 为什么 OOM Killer 会杀容器 | 写成系统物理内存耗尽才杀。容器更常见的是 `--memory` / cgroup 限额到了，宿主机还很闲。 | 先写 cgroup 内存上限。超了内核按 oom_score 杀容器里的进程。整机内存打满才是宿主机级 OOM。 |
| 重要 | 2.k8s | 如果一个 Pod 挂了第 3–4 条 | 写成本地重启失败，ReplicaSet 就再建一个新 Pod。容器崩溃是同一个 Pod 里重启，CrashLoopBackOff 还是这个 Pod。ReplicaSet 只保证 Pod 个数，不因为重启失败换一个。 | 改成：容器挂了 → kubelet 按 restartPolicy 在原地重启。Pod 被删、或节点没了导致 Pod 消失，ReplicaSet 才补一个新的，再交给 Scheduler。 |
| 重要 | 2.k8s | 如果整个 Node 挂了 | 写成给该 Node 上所有 Pod 打不可达污点，并在 Master 上标记待重建。Taint 打在 Node 上。新 Pod 由控制器创建，Scheduler 放到别的 Worker，不是落到控制平面。 | 改成：Node 失联约 40s 变 NotReady，打上 unreachable/not-ready。默认 NoExecute 容忍约 300s 后驱逐。控制器删旧 Pod、补新 Pod，调度到健康节点。 |
| 重要 | 1.Docker | Bind Mount 和 Volume 区别第 2 条 | 写成挂载点里已有文件会自动复制到 Volume。这只发生在空的 named volume 第一次挂载。Bind 从不拷贝，只是挡住原目录。 | 补前提：仅空 Volume 首次使用会从镜像目录拷一份。之后以 Volume 为准。Bind 始终隐藏容器里原文件。 |
| 重要 | 4.分布式 | 锁续期 / 可重入 | 把 Watchdog 和 Hash 重入计数写成 Redis 锁的标准能力。这是 Redisson 的实现。`SET NX EX` 本身不续期、不可重入。Go 社招先讲 Redis 原语，再提客户端。 | 主路径只留：`SET key uuid NX EX`、Lua 校验再删。续期是客户端后台续 TTL。可重入不是 Redis 自带。Go 可以说自己起 goroutine 续，或库未必带 Watchdog。 |

| 重要 | 1.Docker | 为什么很多 Dockerfile 要用 exec | 讲了 exec 换进程保 PID，没对接 Dockerfile 的两种写法。`CMD node app` 这种 shell 形式 PID 1 是 `/bin/sh -c`。 | 补：JSON exec 形式让应用当 PID 1；shell 形式要在脚本里 `exec`。`docker stop` 的 SIGTERM 只给 PID 1。 |

| 重要 | 2.k8s | kube-proxy / 网络 | Service 讲完了，Pod 网络从哪来没写。kube-proxy 不管 Pod IP。 | 补一句：CNI 插件给 Pod 插网卡、分配 Pod CIDR。kube-proxy 只实现 Service 的 ClusterIP/NodePort 规则。 |
| 重要 | 4.分布式 | SET NX EX 整节之后 | 锁超时、误删、Lua 都有。最常追问的失效没写：锁写在 Redis 主库，未复制就 failover，新主上另一台再 SET 成功，两台都以为持锁。 | 补：TTL 到期业务还在跑、以及主从切换双持有，都是 Redis 锁的已知缝。不要承诺强一致。要强租约走 etcd/ZK。 |
| 重要 | 4.分布式 | etcd、ZooKeeper | 只写了「复杂、强一致性」。和 Redis TTL 锁对比的那句没有：租约/临时节点、会话丢了锁自己掉、过半选举。 | 补：etcd 用 lease，ZK 用 ephemeral。节点挂了锁释放。集群靠过半，避免 Redis 那种双主各发一把锁。 |

## 面试高频但几乎没写的

镜像只读、自定义网络 DNS、Service 四种类型、SET NX EX，正文里已经有。缺的是这些能接上现有章节的一面题。不要把容器逃逸写成攻防过程。

### Dockerfile — 有收益列表，缺最终镜像长什么样

多阶段三条好处可以留。一面要看：编译放 `golang` 阶段，运行放 `scratch` / distroless，只拷二进制。`COPY go.mod` 再 `download` 已经点到缓存，顺手写清：源码变了依赖层还能命中。

exec 已经出现。补 JSON 形式和 shell 形式，PID 1 和 `docker stop` 才能对上。

### 探针、HPA、资源

kubelet 里三个探针名字有了，语义写反了，等于没写。补完 liveness / readiness / startup 之后，Deployment「零停机」才站得住：没有 readiness，新 Pod 一进 Service 就会打到还没听端口的进程。

HPA 完全没有。Scheduler 已经在看 CPU/内存，补 request/limit 和「HPA 改 replicas」各一句即可。

### Pause 和 CNI

同 Pod 的 localhost 写了，Pause 没写。kube-proxy 写了，CNI 没写。两句就够：Pause 占网 ns；CNI 给 Pod IP。不要展开 Calico/Flannel 细节。

### 分布式锁失效、脑裂

误删和 Lua 是对的。缺的是 Redis 主从切换后两把锁，以及 etcd/ZK 用租约加过半。一面常把「脑裂」和乱说的「脑残」混在一起：要说的是分区后出现双主，不是骂集群。Redis 锁过 TTL、过 failover 都会双持有；etcd/ZK 过半才选出主。

### 容器逃逸 — 只补边界，不要写混

表里已经有「隔离相对弱、共享内核」。不要写成 OverlayFS 把镜像层写穿（可写层写不进 lowerdir）。常见口子是 `--privileged`、把 `docker.sock` 挂进容器、内核漏洞。Go 一面到此为止。

## 四处建议改口

### Image 和 Container

现在：Image 只读，Container 只写；Container 就是正在运行的。

更好：镜像是只读层叠起来的模板。容器 = 这些只读层 + 一层可写层。读走合并视图，写只落可写层。停掉的容器还在，删掉才丢这层。

### 探针

现在：kubelet 做 Liveness、Readiness、Startup，容器挂了就重启。

更好：活着没有（liveness）才重启；没准备好（readiness）只摘流量；startup 在启动期替前两个挡着。进程自己退出，才是 restartPolicy。

### Secret

现在：Base64 编码加密存储。

更好：Base64 不是加密。Secret 是敏感配置的对象类型，默认仍能被有权限的人读出来。真加密要开 etcd 落盘加密，访问靠 RBAC。

### Redis 锁

现在：SET NX EX，再用 Watchdog 续期、Hash 做可重入。

更好：一条 `SET key 随机值 NX EX` 保证加锁和 TTL 原子；删除用 Lua 对随机值。业务超时和 Redis 主从切换，仍可能两台同时持锁。Watchdog、可重入是客户端加的，不是 Redis 命令。

## 写得比较稳的部分

`1.Docker` 开篇容器共享宿主机内核、虚拟机有 Guest OS，隔离和开销对比能讲圆。自定义 bridge + 内置 DNS、compose 服务名能解析，是对的。PID 1 不注册 handler 就忽略 SIGTERM、所以要 exec 或 tini，这条主链可用。Volume 管持久化、Bind 管开发热更新，方向对。`2.k8s` 里 apiserver 是唯一碰 etcd 的组件、kubelet 走 CRI 调 containerd、Service 的 ClusterIP / NodePort / LoadBalancer / ExternalName、Ingress 要单独装 Controller，这些可以直接背。`4.分布式` 的 SETNX + EXPIRE 两步会永久死锁、value 必须唯一、校验和 DEL 必须 Lua，以及雪花怕时钟回拨，这些是对的。
