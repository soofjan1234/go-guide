## 为什么需要科学上网

主要原因是网络访问会被防火墙（GFW）选择性拦截，常见方式有三类：

1. **DNS 污染**：返回错误 IP，让域名解析失败。
2. **IP 封锁**：直接丢弃发往黑名单 IP 的数据包。
3. **DPI 深度包检测**：识别流量内容或协议特征，发现代理/VPN 后阻断连接。

所以问题不只是“网站在国外”，而是访问路径中的域名、IP、协议特征可能被识别和拦截。

## VPN 的基本原理

VPN（Virtual Private Network，虚拟专用网络）的核心是：在本机和服务器之间建立一条加密隧道。

```txt
你的设备 == 加密隧道 == VPN / 代理服务器 -> 目标网站
```

中间网络通常只能看到你连接了某个服务器，看不到隧道里具体访问了哪些网站、传输了什么内容。

### 既然“外网”被墙了，而 VPN 服务器又在国外，为什么手机能直接连接上它？

因为防火墙不是物理上切断了所有出国网线，而是在做选择性拦截。

它主要拦截两类流量：

1. 已经在黑名单里的 IP 或域名。
2. 协议特征明显、被识别出来的代理或 VPN 流量。

如果一个海外服务器的 IP 还没有被加入黑名单，并且连接过程看起来像正常的 HTTPS 访问，那么这条连接就可能被放行。

```txt
直接访问：
你的手机 -> Google / YouTube -> 被拦截

中转访问：
你的手机 -> 海外代理服务器 -> Google / YouTube
```

关键点：

- 服务器 IP 不能过于暴露。
- 协议特征不能太像传统 VPN。
- 流量最好伪装成常见 HTTPS。

这也是为什么节点可能突然失效：当某个 IP 或流量模式被识别后，就可能被封锁。

## 演进历程

### 第一代：传统 VPN（PPTP / L2TP / OpenVPN）

传统 VPN 的目标比较朴素：在客户端和服务器之间建立一条虚拟专用网络。

连接成功后，系统会多出一张虚拟网卡，流量会被封装进 VPN 隧道，再从 VPN 服务器出口访问目标网站。

```txt
应用流量 -> 虚拟网卡 -> VPN 隧道 -> VPN 服务器 -> 目标网站
```

特点：

- 适合企业远程办公、访问内网、站点互联。
- 对应用透明，配置好后系统流量都能走隧道。
- VPN 协议特征明显，容易被 DPI 识别。

### 第二代：加密混淆（Shadowsocks / SSR）

第二代的思路变了：不再追求完整接管系统网络，而是把重点放在代理和混淆上。

Shadowsocks 更像是一个加密 SOCKS 代理。

```txt
浏览器 / 应用 -> 本地代理 -> 加密连接 -> 远端服务器 -> 目标网站
```

客户端本地会开一个代理端口，浏览器或系统把请求交给本地代理。本地代理再把数据加密后发给远端服务器，由远端服务器访问真实目标。

特点：

- 更轻量，不一定接管全局网络。
- 支持规则分流，只让部分网站走代理。
- 解决了明文问题，但仍可能被统计特征识别。

### 第三代：伪装与 TLS 时代（V2Ray / VMess / Trojan / Xray）

第三代的核心思路是：尽量把代理流量伪装成正常 HTTPS 流量。

因为现代互联网里 HTTPS 流量占比极高，如果代理流量能混在正常 HTTPS 里，就比自定义协议更难被简单区分。

典型链路：

```txt
客户端 -> TLS 加密连接 -> Web 服务器 / 代理入口 -> 目标网站
```

特点：

- 尽量伪装成普通 HTTPS 流量。
- 可使用 WebSocket、HTTP/2、gRPC 等常见 Web 传输方式。
- 更灵活，但配置、证书、域名和路由排查成本更高。

## 怎么选

不是越新越好，主要看场景：

1. **企业内网 / 远程办公**：优先标准 VPN，管理清晰。
2. **个人轻量使用**：Shadowsocks 这类代理简单直接。
3. **复杂网络环境**：V2Ray / Xray / Trojan 更适合做 TLS 伪装和细粒度路由。

简单理解：

```txt
传统 VPN：重在“加密并接管网络”
加密代理：重在“轻量转发和分流”
TLS 伪装：重在“看起来像正常网站访问”
```
