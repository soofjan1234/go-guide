# 协作

## code review

1. 业务逻辑与正确性
    - 需求符合度
    - 边界条件与空值防护
    - 状态机与并发安全：

2. 架构设计与扩展性
    - 单一职责原则（SRP）：一个函数/类是不是干了太多事？
    - 分层边界：业务逻辑有没有污染 Controller / API 接口层？
    - 模块解耦与复用

3. 性能与资源消耗
    - 数据库/存储瓶颈：有没有引起 N+1 查询问题？查询是否走了索引？有没有 `SELECT *`？
    - 内存与 GC 压力：在高频循环里有没有大量分配临时对象（引发 GC 抖动）？
    - 网络与 IO：RPC / HTTP 调用有没有设置合理的超时时间（Timeout）和重试策略？

4. 安全性与防御性编程
    - 注入漏洞：SQL 注入、Shell 注入、XSS / CSRF 攻击防护。
    - 敏感数据处理
    - 越权与鉴权

5. 可观测性与容错
    - 错误处理
    - 日志规范
    - 降级与熔断：核心依赖出现故障时，是否有兜底方案（Fallback）？

## AI生成结果不符合预期怎么办 +4

1. 先验证 AI 生成结果，根据结果进行反馈
2. 会不会是上下文污染，是不是积累太多无关废话，可以清空
3. 会不会一次生成太多功能，直接过载，按模块来写
4. 指出错误的地方，描述清楚要改什么；也可启用plan模式，知道AI会怎么改
5. 最后是规则沉淀，有哪些易犯的错误

# 认知

## 对 AI 的看法？优势和局限是什么？ +1

AI的优势：
1. 能够快速的搭建好一个项目
2. 快速的定位Bug，CodeReview

我的优势：
1. 理解需求，描述给AI
2. AI给的测试边界不全，需要自己考虑更多
3. AI给出技术方案，我来拍板做哪个
