## 一、查：我想知道什么？

第一次打开 Linux 终端，屏幕上只有一个光标。你想先知道「我现在在哪？」输入 `pwd`，按回车。

```console
$ pwd
/home/alice
```

`pwd` 是 **print working directory**。`print` 是在屏幕上显示，`working directory` 是当前工作目录。整条命令的意思就是「告诉我现在在哪个目录」。例子里的 `$` 是终端提示符，你只要输入后面的 `pwd`。你看到的路径可能和这里不同。

接着敲 `whoami` 看你用的是哪个账号，敲 `ls` 看当前目录里有什么。

### 我是谁？我在哪台机器上？

刚连上一台机器，可以用这几条命令认一下环境。

| 想知道什么 | 命令 | 怎么记或怎么看 |
| --- | --- | --- |
| 我用的是什么账号？ | `whoami` | **who am I**，我是谁 |
| 我的用户编号和所属用户组是什么？ | `id` | 联想 **identity**（身份），看 `uid`（用户编号）和 `groups`（所属组） |
| 这台机器叫什么？ | `hostname` | **host name**，主机名 |
| 内核是什么版本？ | `uname -r` | `uname` 可以用 **Unix name** 来记，`-r` 是 **kernel release**，显示内核版本 |
| 还想知道机器架构等信息？ | `uname -a` | `-a` 是 **all**，一次显示内核版本、机器架构等信息 |

例如，`Ubuntu 24.04 LTS` 是发行版的名称和版本。发行版是把 Linux 内核和一套软件打包起来的系统。`uname -r` 显示的 `6.8.0-31-generic` 则是其中的内核版本。

### 这里有什么文件？我怎么走到别的目录？

`ls` 可以记成 **list**，列出目录内容。要进去看看，就用 `cd`，全称 **change directory**，切换当前目录。下面几行可以直接跟着敲。

```bash
ls
cd /etc
pwd
ls -lah
cd ..
cd ~
```

`/etc` 是常见的系统配置目录。路径里的 `.` 表示当前目录，`..` 表示上一级目录，`~` 表示自己的家目录。所以 `cd ..` 是往上走一级，`cd ~` 是回家。

`ls -lah` 可以写成 `ls -l -a -h`。拆开看，三个字母各做一件事。

- `-l` 对应 **long format**，显示权限、所属用户、大小和修改时间等详细信息。
- `-a` 对应 **all**，把名字以 `.` 开头的隐藏项也列出来。
- `-h` 对应 **human-readable**，把大小显示成 `4K`、`20M` 这类易读的形式。可以读成「给人看得顺眼一点」。

### 文件里写了什么？日志刚刚发生了什么？

假设你手边有一个 `app.log`。下面用它演示如何看日志。练习前先进入日志所在的目录，也可以把 `app.log` 换成实际路径。

| 想知道什么 | 命令 | 怎么记或怎么操作 |
| --- | --- | --- |
| 把短文件整个显示出来 | `cat app.log` | `cat` 来自 **concatenate**（拼接），只给一个文件时就把这个文件的内容输出到屏幕 |
| 慢慢翻看长文件 | `less app.log` | 用方向键翻阅，输入 `/error` 搜索，按 `q`（**quit**）退出 |
| 看开头五行 | `head -n 5 app.log` | `head` 是头，`-n 5` 指定五行 |
| 看最后十行 | `tail -n 10 app.log` | `tail` 是尾，日志通常在末尾追加，先看这里就能看到最近的几行 |
| 等着看接下来写入的日志 | `tail -f app.log` | `-f` 是 **follow**，跟着日志往下看，按 `Ctrl+C` 停止跟踪 |

比如你刚触发了一次报错，可以先用 `tail -n 20 app.log` 看末尾附近的记录。想观察报错会不会再次出现，就换成 `tail -f app.log`，留着这个窗口等新日志。

### 日志文件在哪？哪些行里有报错？

先找文件名，再到文件内容里找关键词。假设你在应用目录里，第一步可以这样问。

```bash
find . -type f -name '*.log'
```

`find` 就是找。`.` 指定从当前目录开始，`-type f` 只找普通文件，`-name '*.log'` 按名字找以 `.log` 结尾的文件。引号把 `*.log` 原样交给 `find`，让它去各层子目录里匹配。

找到 `app.log` 之后，用 `grep` 从里面挑出带有 `error` 的行。把下面命令里的文件名换成 `find` 看到的路径。

```bash
grep -in 'error' app.log
```

`-i` 是 **ignore case**，所以 `error`、`Error` 和 `ERROR` 都能匹配。`-n` 是 **line number**，在匹配结果前显示行号。比如看到 `42:ERROR database timeout`，就知道第 42 行写着数据库超时。

### 磁盘还剩多少？哪个目录占得最多？

假设程序说「磁盘空间不足」，你可以从剩余容量一路查到具体目录。

```bash
df -h .
du -sh .
du -h --max-depth=1 . | sort -h
```

1. **当前目录所在的文件系统还剩多少空间？** 用 `df -h .`，可以用 **disk free** 来记。文件系统可以暂时理解为硬盘上存放文件的一块区域，先看输出的 `Avail`（可用容量）。
2. **当前目录合计占了多少？** 用 `du -sh .`。`du` 是 **disk usage**，`-s` 是 **summarize**，只报一个总数，`-h` 仍是 **human-readable**。
3. **哪个子目录占得最多？** 用 `du -h --max-depth=1 . | sort -h`。`--max-depth=1` 只显示当前目录和下一层子目录的用量，`sort -h` 能按 `K`、`M`、`G` 的实际大小排序。

例如，排序后看到了这几行。

```text
24M     ./config
320M    ./cache
2.1G    ./logs
2.5G    .
```

最后一行的 `.` 是当前目录的合计。往上看，最大的子目录是 `./logs`，下一步就知道该去哪一层继续查。 

如果想看内存，用 `free -h`。想知道系统大约还有多少内存可供新程序使用，先看 `available` 这一列。

### 程序在运行吗？哪个进程占资源？

程序运行起来后，系统会为它的进程分配一个编号，叫 **PID**（**process ID**）。如果怀疑程序没启动，可以先按名字找进程。

```bash
ps -ef
pgrep -a bash
top
uptime
```

- `ps -ef` 像给进程拍一张快照。
    - e → every，列出系统里的所有进程。
    - f → full format，用完整格式显示。比如 UID 是进程所属用户，`PPID` 是父进程编号，`CMD` 是启动命令。
- `pgrep -a bash` 可以记成「在进程里做 `grep`」。把 `bash` 换成你要找的进程名，`-a` 让结果同时显示 PID 和完整命令行。
- `top` 会持续刷新。想知道谁在用 CPU 和内存，可以看每行的 `%CPU` 和 `%MEM`。按 `q` 退出。 

### 我的 IP 是多少？服务的端口有人监听吗？

假设你在这台机器上启动了一个 Web 服务，预期它会在 `8080` 端口等请求。端口可以理解为同一台机器上，程序接收网络请求的编号。

| 想知道什么 | 命令 | 怎么记或怎么看 |
| --- | --- | --- |
| 这台机器有哪些 IP 地址？ | `ip addr` | `addr` 是 **address**（地址） |
| 发往其他机器的数据会走哪条路？ | `ip route` | `route` 是路由。`default via` 后面的地址通常是默认网关，也就是默认把数据交给谁转发 |
| 这个地址有回应吗？ | `ping -c 3 127.0.0.1` | `127.0.0.1` 指本机，`-c` 是 **count**，这里发送三次探测 |
| `8080` 有没有程序在等连接？ | `ss -ltn` | `-l` 是 **listening**（监听），`-t` 是 **TCP**，`-n` 是 **numeric**（用数字显示端口） |
| Web 服务能返回 HTTP 响应吗？ | `curl -I http://127.0.0.1:8080/` | `-I` 是大写字母 I，发送 `HEAD` 请求查看响应头。先看第一行的状态码，例如 `200` |

`ss -ltn` 可以用 **socket statistics** 来记。这里先看 `Local Address:Port` 一列就够了，例如 `127.0.0.1:8080` 表示服务在本机地址的 `8080` 端口等连接。再用 `curl` 发一次请求，就能继续确认 Web 服务有没有回应。

### 系统服务启动了吗？它记录了什么日志？

在用 **systemd** 管理服务的机器上，可以用 `systemctl` 查服务状态，用 `journalctl` 查系统日志。下面用 `nginx` 举例，实际操作时换成机器上已有的服务名。

```bash
systemctl status nginx
journalctl -u nginx -n 20
journalctl -u nginx -f
```

- `systemctl status` 先看 `Active` 一行。`active (running)` 表示服务正在运行，`failed` 表示服务发生了故障，可以继续看日志。
- `journalctl` 里的 **journal** 是日志。`-u` 是 **unit**，用来选中某个 systemd 管理的单元，这里指定的是 `nginx` 服务。`-n 20` 只取最近二十条日志。
- `-f` 还是 **follow**，和 `tail -f` 一样，等着看新日志。按 `Ctrl+C` 停止。

有些服务把日志写在独立文件里，可以用前面的 `tail` 或 `grep` 来查。
