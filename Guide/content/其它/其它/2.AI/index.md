# 协作

## code review

1. 业务逻辑与正确性
    - 需求符合度
    - 边界条件与空值防护
    - 状态机与并发安全：

2. 架构设计与扩展性
    - 单一职责原则（SRP）：一个函数/类是不是干了太多事？
    - 分层边界：业务逻辑有没有污染 Controller / API 接口层？
    - 模块解耦与复用

3. 性能与资源消耗
    - 数据库/存储瓶颈：有没有引起 N+1 查询问题？查询是否走了索引？有没有 `SELECT *`？
    - 内存与 GC 压力：在高频循环里有没有大量分配临时对象（引发 GC 抖动）？
    - 网络与 IO：RPC / HTTP 调用有没有设置合理的超时时间（Timeout）和重试策略？

4. 安全性与防御性编程
    - 注入漏洞：SQL 注入、Shell 注入、XSS / CSRF 攻击防护。
    - 敏感数据处理
    - 越权与鉴权

5. 可观测性与容错
    - 错误处理
    - 日志规范
    - 降级与熔断：核心依赖出现故障时，是否有兜底方案（Fallback）？

## 操作

一个需求到来之后：

1. 会使用shape work 来确定做什么 不做什么 约束 验收；
2. 然后使用design work 来去设计流程、接口、数据库、技术；
3. 接着使用plan work 来拆成可执行的、分段的计划；
4. build work 按计划tdd实现；
5. 最后的review复盘代码、操作、文档
