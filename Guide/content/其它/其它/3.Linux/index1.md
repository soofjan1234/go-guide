## 进程、协程、线程对比 +3

1. 进程资源分配的最小单位；线程是CPU调度的最小单位；协程是轻量级线程
2. 协程是用户态的，切换开销最小，适合 I/O 密集高并发；其他两个需要系统调用，切换开销较大
3. 进程资源隔离；线程共享进程地址空间等资源；协程共享进程内存，由 runtime 映射到 OS 线程（M:N）

## 进程通信 +1

1. 匿名管道（`pipe`，常用于有亲缘关系的进程）与命名管道（FIFO，可供无亲缘关系的进程通信）。
2. 信号是异步通知，如 SIGTERM；信号量是计数同步原语，用于协调资源访问，两者不是同一种机制。
3. 共享内存
4. 消息队列
5. 套接字

子进程退出后，父进程若未调用 `wait` 回收退出状态，会留下占用 PID 表项的僵尸进程；父进程先退出时，孤儿进程会被 init 或其他 subreaper 接管。Go 使用 `os/exec` 启动子进程后也要调用 `Wait`。

## 脚本第一行（Shebang）作用 +1

告诉系统用哪个解释器执行脚本。
- `#!/bin/bash`：路径固定，如果 bash 不在 `/bin` 下会报错。
- `#!/usr/bin/env bash`：更便携，会从当前用户的 `PATH` 中查找 bash。

## 修改权限与执行程序

面试回答：先用 `ls -l` 查看文件权限。修改权限用 `chmod`，修改所有者和所属组用 `chown`。程序缺少执行权限时，给需要执行它的用户添加 `x` 权限。

```bash
ls -l app
chmod u+x app          # 给所有者添加执行权限
chmod 755 app          # rwxr-xr-x
chown root:root app    # 修改所有者和所属组
./app                 # 执行当前目录里的程序
```

`chmod` 的三位数字依次表示所有者、所属组、其他用户；每位按 `r=4`、`w=2`、`x=1` 相加。`755` 表示所有者可读写执行，其余用户可读执行；`644` 表示所有者可读写，其余用户只读；`600` 表示仅所有者可读写，常用于私钥文件。

## Vim 编辑、保存与复制粘贴

面试回答：用 vi 或 vim 编辑，`i` 进入插入模式，`Esc` 返回普通模式，`:wq` 保存退出，`:q!` 放弃修改退出。普通模式下 `dd` 删除当前行，`yy` 复制当前行，`p` 粘贴。

| 操作 | 命令 |
| --- | --- |
| 打开文件 | `vim app.conf` |
| 进入插入模式 | `i` |
| 返回普通模式 | `Esc` |
| 保存 | `:w` |
| 保存并退出 | `:wq` |
| 放弃修改并退出 | `:q!` |
| 删除当前行 | `dd` |
| 复制当前行 | `yy` |
| 粘贴 | `p`；复制整行时放到当前行下方 |

## 查看文件、过滤内容与跟踪日志

面试回答：小文件用 cat，大文件用 less；过滤内容用 grep，忽略大小写加 `-i`，显示行号加 `-n`。持续跟踪日志用 tail，日志轮转时用 `tail -F`。

```bash
cat app.log
less app.log
grep 'error' app.log
grep -i 'error' app.log      # 忽略大小写
grep -n 'error' app.log      # 显示匹配行的行号
tail -n 100 -f app.log       # 先显示最后 100 行，再跟踪新增内容
tail -F app.log              # 按文件名跟踪，并在文件重新出现时重试
```

`less` 用方向键翻阅，`/关键词` 搜索，`q` 退出；跟踪日志时用 `Ctrl+C` 停止。

## 网卡、IP 地址、路由表与端口占用

面试回答：网卡和链路状态用 ip link，IP 地址用 ip addr，路由表用 ip route。监听端口和对应进程用 ss，也可以用 lsof 指定端口查询。

```bash
ip link
ip -br addr
ip route
sudo ss -lntp
sudo ss -lntup
sudo lsof -nP -iTCP:8080 -sTCP:LISTEN
```

`ss -lntp`：`l` 表示监听，`n` 使用数字显示地址和端口，`t` 表示 TCP，`p` 显示进程；加 `u` 同时查看 UDP。`ip addr` 查地址，`ip route` 查路由，不能混用。

网络接口包含物理接口和虚拟接口，接口数量不能直接当作物理网口数量。NAS 的芯片、内存、盘位和物理网口规格统一维护在项目文档的“NAS 产品规格”一节。

## 查看进程、终止进程与信号

面试回答：用 ps 查看进程，pgrep 按名称查找。终止时先发送 TERM，让程序有机会清理资源；不响应时再用 KILL 强制终止。按名称发送信号可以用 pkill。

```bash
ps -ef
pgrep -af LincAlbum
kill -TERM 1234            # 请求指定 PID 退出
kill -KILL 1234            # 强制终止，等同于 kill -9 1234
pkill -TERM -x LincAlbum   # 按完整进程名匹配并发送信号
```

上面的 PID 是示例，执行前应替换为实际目标。`kill` 默认发送 SIGTERM，并非默认强杀；`pkill` 可能匹配多个进程。

| 信号 | Linux 常见编号 | 含义 |
| --- | --- | --- |
| SIGTERM | 15 | 请求终止，可捕获并处理；能否优雅退出取决于程序实现 |
| SIGKILL | 9 | 强制终止，不能捕获、屏蔽或忽略，程序无法执行退出清理 |
| SIGINT | 2 | 中断，终端 Ctrl+C 通常向前台进程组发送它 |
| SIGHUP | 1 | 挂断；部分服务用它触发配置重载，取决于服务实现 |

使用信号名比记数字更直观。强杀也可能等待不可中断的内核操作结束，并非任何情况下都立即消失。
