## lua的优势

如果你不用 Lua，在处理“先读再改”的业务（如扣减库存、加锁）时，通常需要：

1. 客户端发送 GET 去读取数据；
2. 客户端在内存中计算逻辑；
3. 客户端发送 SET 将新值写入 Redis。

这个过程需要 3 次网络 RTT（往返时延），且在步骤 1 和步骤 3 之间，极其容易发生并发并发竞态（Race Condition）。

使用 Lua 脚本可以带来三大核心优势：

1. 绝对的原子性（Atomicity）
Redis 会将整个 Lua 脚本作为一个整体放入单线程队列中执行。在脚本执行期间，其他任何客户端发送的命令都会被阻塞，直到脚本完全执行结束。

效果： 彻底杜绝了并发安全问题，不需要像在客户端那样加复杂的分布式锁或使用 WATCH/MULTI/EXEC（Redis 事务）。

2. 减少网络开销（Reduce Network Overhead）
将多个命令和逻辑打包成一个 Lua 脚本发送给 Redis 服务端，只需 1 次网络 RTT，大大降低了高并发下的网络延迟和 CPU 消耗。

3. 代码复用与客户端轻量化
逻辑交给 Redis 内部执行，客户端只需传递参数即可，减少了客户端与 Redis 之间频繁传输中间结果的数据量。
