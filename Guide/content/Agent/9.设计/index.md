# 如果要做一个智能客服类 AI 应用，整体链路怎么设计？

一般会先做问题分类，区分 FAQ、知识问答、工具调用和人工转接。

简单固定问题走模板回复，知识类问题走 RAG，查订单、查物流、查账户这类走工具调用，高风险或低置信度问题直接转人工。

核心链路要有会话管理、权限校验、敏感词过滤、日志追踪和效果评估，不然上线后很难控风险。

# 如何优化一个Agent项目

1. 看数据：先接上监控（如 LangSmith），攒几百条真实测试题，算清楚当前的成功率、响应速度和成本。
2. 找病因，分模块重构：
   - 规划能力不足：优化prompt结构，引入反思机制。
   - 找不着工具：重构tool description。
   - 答非所问，丢失上文：引入滑动窗口，做好记忆。
   - 响应太慢：我们可以做小模型分级路由、并行工具调用
3. 加护栏：设置最大重试次数防止死循环，高风险操作（如删库、发邮件）必须经过人工确认。

# 一个agent什么时候决定结束 

1. 目标已达成
2. 命中了预设的状态机节点
3. 触发了熔断，比如说最大轮次限制，token限制。

# 一个agent什么时候决定问用户

1. 关键参数缺失
2. 语义不明确
3. 高风险操作

# 失败恢复怎么设计

agent的一个失败呢可能分成好几类，所以要按类型进行一个不同的错误处理

1. 接口超时，我们可以限时的一个限次数的一个重试。
2. 参数缺失的话，我们可能要进行一个追问。
3. 如果是选错了工具就要进行一个降级。
4. 外部系统不可用，就要终止，并且返回失败的原因。
