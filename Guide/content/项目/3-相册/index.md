# 一、算法
## RKNN 平台是什么？和你的nas有什么关系

推出基于瑞芯微芯片（如RK3568、RK3588）的 ARM 架构 NAS，可以支持 RKNN 平台，通过 JNI 接口调用 native 层能力，实现模型推理。

降本增效：相比于 Intel 的 x86 芯片，价格更便宜、功耗极低，因为有 NPU 的存在，它的 AI 算力能直接吊打几千元的 Intel 处理器。

## 人脸检测和识别的流程

1. 人脸检测：使用 yunet rknn 模型，返回人脸的位置信息
	1. retinaface速度快，但漏检多
	2. scrfd误检偏多
2. 识别：使用了 mobileFaceNet 模型 ，并提取人脸特征向量
	1. sface rknn 精度一般
	2. arcface、iResNet 速度不如 mobileFaceNet
3. 人脸聚类：计算人脸特征之间的距离矩阵，再使用DBSCAN聚类，并得到每个类别的中心特征向量
4. 人脸分类：计算新人脸特征与聚类中心特征的距离，根据阈值来确定是加入还是创建新类别

## DBSCAN算法

拿社交圈举例：

1. 两个门槛：
    1. **eps（邻域半径）**：**"社交距离"**。就是你觉得多近才算"朋友圈"。比如 1 米内。
    2. **MinPts（最小点数）**：**"成群结队门槛"**。一个人带几个小弟才算"社交达人"？比如 3个。
2. 三个身份
    1. **核心点（大佬）**：1米内有3个
    2. **边界点（小弟）**：1米内不足3个，但在大佬的1米内
    3. **噪声点（独行侠）**：身边没人，也不在大佬圈子里
3. 聚类流程
    1. 随机抓一个人，看是否是大佬，是就把小弟都拉进来
    2. 再看小弟，是否也是大佬，如此套娃
    3. 知道所有人都被判定身份

1. 启动时加载模型

## 照片的选取测试有什么讲究

人脸检测用了 WIDER val 全量 3226 张

人脸识别/验证 LFW (Labeled Faces in the Wild) 人脸识别数据集 1000 pairs

检测指标是：
 - recall：真实目标有多少被找到了; 
 - precision：检测出来的人脸有多少是真的；
 - AP：综合结果
 - 通用性能：内存、cpu、峰值、耗时

## 自己建立数据集该怎么做

1. 先明确任务和业务场景。比如是做人脸检测、人脸识别；室内还是室外、光照如何，是否有遮挡、模糊特殊情况。

2. 基于真实业务分布采集数据，可以来自用户授权数据、内部测试采集、公开数据集补充和合成增强。

3. 制定标注规范。检测任务标人脸框、关键点、遮挡、模糊、姿态等；

4. 最后划分`train`（训练集）、`val`（验证集）、`test`（测试集）。

# 二、模糊

## 技术选型

选拉普拉斯方差做模糊检测，是因为模糊图片的边缘和高频细节会明显减少，而拉普拉斯算子正好对边缘变化敏感。

清晰图的拉普拉斯方差通常更大，模糊图更小，所以可以用一个阈值快速判断清晰度。

除此之外还可以使用 Sobel 等梯度方法，还可以训练 CNN 模型直接输出图像清晰度评分。拉普拉斯方差最简单高效

## 大图缩放会影响吗

清晰的边界：黑白交界处，前一个像素是 0（黑），下一个像素瞬间变成 255（白）。这种断崖式的变化就是“清晰”。

原本清晰的大图缩放后，由于它原本的边界极其陡峭，缩放后的黑白交界依然是断崖式的（比如从 10 直接跳到 240）

## 具体步骤

1. 缩放：如果原图宽度 <= 512：不缩放，直接用原图如果原图宽度 > 512：等比例缩放到宽度 512
2. 转灰度图：彩色图会转成灰度，因为模糊判断主要看亮度边缘变化，不依赖颜色
3. 并行计算方差，小于阈值则为模糊，
## 数据集

1. 香港中文大学和希腊信息技术研究所
2. 人像模式、运动模糊效果不是很好

# 三、相似检测
## 技术选型

第一类是感知哈希算法，例如 aHash、dHash、pHash，通过生成视觉特征哈希并计算汉明距离判断相似度；
- aHash (Average Hash - 平均哈希)：极快，比较扁平，适合粗筛
- pHash (Perceptual Hash - 感知哈希)：它更关注图片整体视觉特征，速度一般，免疫一定程度的裁剪
- dHash (Difference Hash - 差异哈希)：更关注图片局部特征，对比的是相邻像素的“相对差值”，适合连拍照片

第二类是局部特征匹配，例如 SIFT、ORB，通过关键点和描述子匹配解决裁剪、旋转和尺度变化问题；

第三类是深度学习方法，使用 ResNet 等模型提取图片 Embedding，再通过余弦相似度或向量检索判断相似度。

图片解码轻量，pHash、dHash可缓存。SIFT/ORB 特征匹配太重，深度学习要占算力和存储
## 数据集

1. California-ND Dataset（加州近重复数据集） 701张
2. INRIA Holidays Dataset（假期照片数据集） 1491张

# 四、其它

## 优化

因为模糊、重复检测比较耗时，所以做了三层优化，对应简历里「增量扫描、特征缓存、批量处理」。

1. 增量扫描

- 取最近一次完成的任务的开始时间作为基准
- 查照片中 创造时间或修改时间大于基准时间的照片

2. 特征缓存

- `SHA1 → dHash + pHash`，跨任务、跨扫描复用。
- 模糊检测阶段算出的 `ClearScore` 写入 `clearPhotos`，重复检测选 Keeper 时不再重算拉普拉斯。

3. 批量 / 并发处理

- Worker 数 = `min(NumCPU, 8, 照片数)`，并行算拉普拉斯方差
- **写库顺序执行**（适配 SQLite 单连接写，避免锁竞争）
- 清晰图结果带 `SHA1`、`ClearScore` 直接传给下一阶段

4. BK-tree / VP-tree：在汉明距离度量空间里做近邻搜索

## 搜索

1. 鉴权和解析请求体：时间范围、分页、关键词、搜索类型
2. 按各类搜索加条件：比如收藏、人脸、地点
3. 先构造一个gorm查询条件，然后统一进入BaseQuery做真正查询
4. 最后检查原文件是否真的存在；如果文件已经没了，会异步提交清理任务
