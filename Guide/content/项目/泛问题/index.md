# 项目

## 选型关键点

1. 要解决的核心问题

## 优势/对比

从硬件来说，全固态设计、零噪音，散热也做的好
从软件来说，UI有做美化，对用户友好，我们也致力于提升性能

## Docker

Docker 项目主要封装 Docker Engine API，提供镜像、容器、网络和基础状态管理能力。比如查询本地镜像、删除镜像、创建容器、启停容器、查询容器状态、端口映射、挂载目录、环境变量配置等。

拉镜像是长耗时任务，所以接口先创建任务并返回 taskId，后端异步执行 docker pull，同时读取 Docker daemon 返回的 JSON stream。前端通过 SSE 订阅这个 taskId，后端把每一段进度事件转成 SSE event 推给前端。

SSE 比轮询实时性好、实现简单；如果要双向控制才考虑 WebSocket

## 排查/用户反馈

如果有报错，前端捕获报错的traceID，通过接口返给后端，后端抓取日志相关部分，导出压缩包

如果功能不正常，尝试先在测试机上复现，不能复现就提前埋点

对于慢查询，不让业务代码到处直接 db.Query()，而是统一经过一个 DAO/helper记录时间，如果稳定出现，会同时配套explain然后写入慢查询诊断日志

## 数据库优化

在code review中，发现分页查询又可以优化的地方，可以加联合索引user_id、is_dir、modified_at、filming_time

但目前排序逻辑里有 CASE WHEN filming_time ELSE modified_at，会让索引效果变差。所以我会考虑冗余一个 sort_time 字段

写入或扫描照片时提前计算一个统一的排序字段，比如 sort_time，优先取拍摄时间，没有拍摄时间就取修改时间。查询时直接按 sort_time DESC, id DESC 排序，并建立联合索引

分页也从 OFFSET 改成游标分页，比如带上上一页最后一条的 sort_time 和 id
