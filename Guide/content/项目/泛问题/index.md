## Docker

Docker 项目主要封装 Docker Engine API，提供镜像、容器、网络和基础状态管理能力。比如查询本地镜像、删除镜像、创建容器、启停容器、查询容器状态、端口映射、挂载目录、环境变量配置等。

拉镜像是长耗时任务，所以接口先创建任务并返回 taskId，后端异步执行 docker pull，同时读取 Docker daemon 返回的 JSON stream。前端通过 SSE 订阅这个 taskId，后端把每一段进度事件转成 SSE event 推给前端。

SSE 比轮询实时性好、实现简单；如果要双向控制才考虑 WebSocket

## 数据库优化

### 媒体分页与时间轴查询优化

在媒体库规模变大后，媒体分页接口开始出现稳定的慢查询。通过 OpenTelemetry 采集 NAS 端的接口链路、SQL 耗时和数据库调用栈后，慢查询会持续上报到云端监控中心。

通过Explain query plan查看到
|--SEARCH media_infos USING INDEX idx_media_infos_deleted_at (deleted_at=?)
`--USE TEMP B-TREE FOR ORDER BY

进一步分析 SQL 后发现，旧实现存在几个问题：

1. 分页过滤使用 `modified_at`，但业务真实排序时间并不总是文件修改时间，还可能来自拍摄时间。
2. 排序使用 CASE 表达式动态选择 `filming_time` / `modified_at`，数据库难以充分利用索引。
3. 用的索引也只是`modified_at`

因此本次优化将媒体查询统一收敛到 `sort_time` 字段。`sort_time` 在写入或更新媒体信息时提前计算好，用来表达业务上的真实排序时间。查询阶段不再临时通过 CASE 表达式计算排序值，而是直接使用稳定字段完成过滤、排序和聚合。

测试比对性能快了7倍
