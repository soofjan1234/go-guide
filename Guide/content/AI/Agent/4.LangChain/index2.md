# Runnable

Runnable 是统一的执行接口，提示词、模型、解析器和组合后的链都可以按这个接口调用。

| 方法 | 用途 |
| --- | --- |
| `invoke()` | 处理一次输入 |
| `batch()` | 处理一组输入 |
| `ainvoke()` | 异步处理一次输入 |
| `stream()` | 分批读取执行输出 |

`batch()` 不等于模型服务商的离线批处理接口；是否能逐 Token 流式输出，也取决于链上的组件支持。

## LCEL

LCEL 用 `|` 组合 Runnable，比如 `prompt | model | parser`。

前一步的输出作为后一步的输入。统一调用接口不代表类型自动对齐：模型返回消息，下一步需要文本时要转换；提示词需要多个变量时要组织成字典。

# 数据流

## 顺序：RunnableSequence

清洗文本 → 生成提示词 → 调用模型 → 解析结果。

每一步依赖前一步结果，用 `|` 串起来。先检查各步骤输入输出，避免把消息对象直接当作业务字段。

## 函数包装：RunnableLambda

把普通函数包装成 Runnable，适合取字段、清洗文本、转换类型和计算。

输入是字典时，函数收到的是整个字典。参数名字叫 `question`，不会自动取出同名字段；仍要读取 `data["question"]`。

函数包装不等于模型调用，它执行的是你提供的函数。

## 并行：RunnableParallel

把同一份输入交给多个分支，按字段名汇总结果。

比如同一篇文章分别生成摘要和关键词，最后得到含两个字段的字典。

1. 分支之间应没有执行依赖。
2. 各分支拿到同一个完整输入，不会按分支名称自动取字段。
3. 不要依赖并行分支修改共享输入。
4. 并行受限流和资源影响，不保证一定更快。

### 字典简写

字典与 Runnable 通过 `|` 组合时，可以转为并行分支：键是输出字段名，值是该分支的处理方式。

单独创建的普通字典仍然是字典，没有自动获得 `.invoke()`。

## 透传与补字段：RunnablePassthrough

`RunnablePassthrough()` 原样保留输入。`assign(...)` 要求字典输入，保留原字段，再计算并添加字段；同名字段会被覆盖。

例如 RAG 的数据可以依次变成：

1. `question`、`docs`。
2. 生成资料文本，增加 `context`。
3. 根据问题与资料生成回复，增加 `answer`。

这里应分两次 `assign`：先生成 `context`，下一步再生成依赖它的 `answer`。同一次 `assign` 的分支不能依赖另一个分支刚生成的值。

### Lambda 与 Passthrough 的区别

Lambda 用函数返回值替换当前输入；Passthrough 保留输入，`assign` 在字典上补充字段。

## 条件路由：RunnableBranch

从上到下匹配条件，执行第一个命中的分支；没有命中时执行默认分支。

比如先判断是否为 FAQ，再选择模板或知识问答。条件由程序定义；如果需要模型分类，可以先得到分类结果，再进行路由。

# 使用边界

LCEL 适合组合顺序、并行和条件数据流。循环、复杂共享状态、持久化与人工中断，通常放到 LangGraph 或其他控制程序中处理。

排查链路时，先看哪一步的数据形态不符合预期，再看模型行为。模型没答对和字段没传对，是两类问题。
