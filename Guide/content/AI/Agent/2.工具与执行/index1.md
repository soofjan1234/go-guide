## Tool Calling

模型生成工具名和参数，程序校验后执行，再把结果交回模型。

比如查询工单：模型请求 `get_ticket(ticket_id)` → 程序校验工单号和用户权限 → 调接口 → 返回状态 → 模型整理回复。

### 调用流程

1. 提供工具名称、用途、参数 Schema。
2. 模型选择工具，生成调用请求。
3. 程序校验参数、权限和操作目标。
4. 执行工具，返回成功结果或明确错误。
5. 按调用 ID 回填结果，模型继续处理或回答。

一次模型输出可能包含多个工具调用。互不依赖且允许并发的调用可以并行；后一步需要前一步结果时，应顺序执行。

### Schema 正确就能直接执行吗

不能。参数格式合法，不代表工单存在、用户有权限，或收件人是正确的人。Schema 校验之后，还要做业务校验。

## Skill

Skill 保存一类任务的操作说明和相关资源，比如“发布文章时如何处理图片、如何检查结果”。它可以引用脚本和模板，但实际操作仍由程序或工具执行。

通常先加载名称和简介，命中任务后再加载完整说明，需要时再读资源。这种按需加载方式可以减少无关内容进入上下文。

## MCP

MCP 统一外部能力的发现和调用方式，减少各个应用重复编写接入适配。

1. **Host**：运行模型和工具的应用，管理接入与权限。
2. **Client**：Host 内与 MCP Server 通信的组件。
3. **Server**：提供工具、资源和提示词模板。

工具用于执行操作，资源提供数据，提示词提供可复用模板。常见传输包括本地 stdio 和远程 Streamable HTTP，具体按协议版本与服务实现确认。

### MCP 接进来就能自动完成任务吗

不能。MCP 解决能力怎么接入，模型和控制程序仍要决定何时调用、如何校验、失败怎么办。

## A2A

A2A 面向 Agent 之间的能力发现、任务委派和结果交换。比如客服 Agent 把排障任务交给另一个技术支持 Agent。

多个 Agent 在一个进程里协作，不一定需要 A2A；有跨系统任务协作需求时再考虑。

## 区别

| 概念 | 解决什么问题 |
| --- | --- |
| Tool Calling | 这次调用哪个工具、传什么参数 |
| Skill | 这类任务应该怎么做 |
| MCP | 外部工具和资料怎么统一接入 |
| A2A | 不同 Agent 怎么委派和交换任务 |
