# Agent 的基础概念
## Agent 是什么

Agent 围绕一个目标，根据当前信息决定下一步，调用工具，再根据结果继续处理。

比如“查一下订单为什么没到”：查订单 → 查物流 → 判断异常 → 回复用户。下一步查什么，取决于前一步的结果。

## 组成

1. **模型**：理解请求，选择下一步，整理回答。
2. **工具**：查数据、调用接口、读写文件。
3. **状态与记忆**：保存目标、执行进度、历史消息和有用资料。
4. **控制程序**：执行工具，校验权限和参数，处理错误，限制轮次和费用。

规划可以由模型临时完成，也可以拆成单独模块；简单任务不必单独设置规划器。

## 运行过程

用户请求 → 组装上下文 → 调用模型 → 校验并执行工具 → 回填结果 → 再调用模型。

1. 把目标、约束、已有信息和可用工具告诉模型。
2. 模型直接回答，或者提出工具调用请求。
3. 程序校验工具名、参数、权限，再执行。
4. 把真实执行结果交回模型，继续下一步。
5. 达成目标就结束；缺关键信息就追问；超过预算或无法继续就停止。

**模型提出动作，程序执行动作，结果必须核验。** 模型说“已经发出邮件”，不能替代邮件接口的成功回执。

## 与普通聊天、工作流的区别

| 方式 | 下一步由谁决定 | 例子 |
| --- | --- | --- |
| 普通聊天 | 通常只生成回复 | 解释退款规则 |
| 工作流 | 程序预先规定步骤和分支 | 识别意图 → 查订单 → 生成回复 |
| Agent | 模型根据当前结果选择动作 | 自己决定先查什么、是否补查、何时结束 |

工作流也能调用模型和工具。区别主要看执行路径由程序规定，还是由模型动态选择。

### 什么时候需要 Agent

目标明确，但步骤无法提前完全确定，需要根据结果继续探索时可以考虑。

步骤固定就用工作流；一次检索加回答就能完成的任务，不必增加自主循环。循环会增加调用次数、延迟和出错机会。

# 幻觉
## 模型怎么生成回答

以常见的自回归生成模型为例：输入变成 Token ID → 模型计算下一个 Token 的概率 → 选出一个 Token → 接到已有内容后面 → 继续生成。

模型是在生成内容，不是每次都从数据库查出事实，所以回答流畅不代表内容正确。

## 幻觉与执行错误

1. **模型编造**：生成了看似合理、实际没有依据的内容。
2. **资料有问题**：检索错了、资料过期，或者混入了无关内容。
3. **工具调用错误**：工具选错、参数填错、返回结果被误读。
4. **多步误差累积**：前一步判断错误，后面的计划跟着跑偏。

### 怎么降低风险

1. 输入端：高质量 RAG、Prompt 边界声明、确定性 Schema
2. 过程端：任务拆分、严格工具校验、确定性代码兜底
3. 输出端：Self-Reflection、Critic Agent 审核、Guardrails 过滤
4. 权限端：把高风险动作交给人确认
