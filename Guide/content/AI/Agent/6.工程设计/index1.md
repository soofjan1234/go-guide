# 流程设计

## 客服 Agent 怎么设计

接收问题 → 识别任务 → 查资料或调用工具 → 生成回复草稿 → 检查 → 回复或转人工。

1. 固定 FAQ 可以用模板，业务知识走检索，订单状态走授权接口。
2. 涉及退款、修改账户等操作，先校验身份与权限。
3. 资料不足或相互冲突时补查、追问或转人工。
4. 保存每步输入、工具结果和最终处理状态，便于排查。

# 执行控制

## 什么时候结束

1. 目标达成，并拿到必要证据。
2. 到达明确的业务终态，如已回复、已转人工。
3. 触发轮次、Token、费用或总时长限制。
4. 缺少继续执行的条件，返回缺口或失败原因。

模型输出“完成”只是一条信号。创建工单要有工单号，发送邮件要核验发送结果，不能只检查回复文字。

## 什么时候问用户

1. 缺少不能可靠推断的关键参数。
2. 存在多个解释，选择会影响结果。
3. 操作需要授权或审核，当前授权范围不足。

可以从现有资料确定的信息先查，普通执行步骤不必反复询问。

# 评估与优化

## 怎么评估

先准备包含正常任务和失败场景的任务集，再检查完整结果。

1. **任务成功率**：是否满足预先定义的业务目标。
2. **工具正确性**：选对工具、参数正确、结果处理正确。
3. **证据质量**：回答有依据，引用支持对应结论。
4. **运行成本**：轮次、Token、费用、延迟。
5. **人工介入**：介入是否必要，哪些步骤频繁卡住。

报告结果时说明样本量、任务类型、模型版本和判断标准。小样本成功率不能直接代表线上效果。

## 要记录哪些日志

任务 ID、模型与提示词版本、每步状态、工具调用与错误、耗时、Token 用量和最终结果。敏感内容脱敏，控制日志访问权限。

有完整执行链路，才能分清是模型判断错、检索漏了，还是工具执行失败。

## 怎么优化

| 问题 | 先查什么 | 常见改法 |
| --- | --- | --- |
| 选错工具 | 工具说明是否重叠、任务是否明确 | 改名称和说明，缩小工具范围 |
| 资料答不上 | 召回、资料完整性和版本 | 调整分块与检索，必要时重排 |
| 丢失上文 | 关键状态是否进入本轮输入 | 保存结构化状态，改摘要与检索 |
| 响应慢 | 模型、工具、检索各自耗时 | 减少轮次和输出，独立调用并行 |
| 费用高 | 输入和输出 Token、重复调用 | 精简上下文，缓存只读结果，按任务选模型 |
| 经常重复动作 | 恢复位置与执行回执 | 补幂等和结果核验 |

改完用同一批任务对比，确认成功率、成本和延迟的变化，不能只凭几次聊天感觉更好。
