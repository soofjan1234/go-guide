GO RUNTIME / GMP

Go GMP 调度机制

M 是工人，G 是任务，P 是工位与资源包，schedt 是全局调度中心。
M 跑 G，必须先绑定 P。
01 / GOROUTINE

G：可挂起、可恢复、可迁移的任务

G 对 runtime 来说是一份执行快照。它带着栈、PC、SP，也带着 runnable、running、waiting、syscall 等调度状态。

go func() {
  // user task
}()
执行现场栈、PC、SP、上下文。切回来时还能接着跑。
调度状态可运行、运行中、等待中，或者正在系统调用。
可迁移不固定绑定某个 M，必要时可以换线程继续执行。
业务视角就是你用 go 关键字启动的那份任务。
G = 可调度的执行单元。
02 / MACHINE

M：真正跑在 CPU 上的线程

M 是 OS thread。业务 G 放在 curg 上运行；调度、切换、mcall 这类 runtime 工作通常走 g0 这条专用调度栈。

M
拿到一个可运行 G
P
先绑定 P，获得运行资源
g0
调度和切换在后台工作台完成
curg
当前正在执行的业务 goroutine
g0 像后台工作台，避免污染业务 G 的栈。
03 / PROCESSOR

P：最容易被低估的资源包

P 不是物理 CPU，而是运行 goroutine 需要的一组 runtime 资源。最关键的是本地运行队列。

runnext下一跳优先执行位。
runq[256]本地普通队列，多数访问无锁。
mcache小对象分配缓存。
gFree / pcache复用 G 对象和页级缓存。
没有 P 的 M，就像没有工位的工人。
04 / SCHEDULING

本地优先，全局兜底，窃取均衡

M 绑定 P 后，先查本地 runq；本地没有，再看全局队列；还没有，就去别的 P 偷一部分 G。

local first，global fallback，work stealing。
05 / PREEMPTION

抢占：防止一个 G 独占 CPU

协作式抢占依赖函数调用处的 stack check；Go 1.14 起，信号式抢占可以通过 SIGURG 和 asyncPreempt 主动把 G 抢下来。

协作式等检查点，信号式主动注入 asyncPreempt。
06 / NORMAL BLOCK

普通阻塞：只让 G 等

channel、锁、time.Sleep 这类等待，通常阻塞的是 G。M 和 P 不解绑，继续去跑别的 G。

条件满足后，ready / runqput 把 G 放回可运行队列。
07 / NETPOLL

网络阻塞：G 挂到 fd 上

Read/Write 暂时不可进行时，G park，fd 与事件记录到 pollDesc。内核通知就绪后，netpoll 把 G 叫回队列。

fd 就绪由内核通知，netpoll 负责唤醒 G。
08 / SYSCALL

系统调用阻塞：释放 P

长时间 syscall 会拖住 M，所以 runtime 在 entersyscall 路径释放 P，让其他 M 接管资源继续跑 runnable G。

syscall 返回后，G 优先尝试重新拿 P；失败则进入全局队列。
SUMMARY

只记这条链路

理解 GMP，不是死记结构体，而是看清任务、线程、资源包和全局协调之间怎么配合。

1M-P 绑定后跑 G。
2本地优先，全局兜底。
3抢占防止长任务独占 CPU。
4阻塞时释放能释放的调度资源。
后面再看 findRunnable、sysmon、netpoll，就会顺很多。
