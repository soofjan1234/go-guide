# 面试准备

根据目标公司、岗位和候选人的真实简历，生成两条可直接用于面试的精炼中文回答，并提供便于记忆的关键词。

## 输入与事实来源

1. 要求用户提供公司名称和岗位名称；已提供岗位 JD 时一并使用，不额外索要。
2. 每次都读取 `D:\otherWorkspace\go-guide\IV-arena\resume.tex`，只提取与岗位相关的技能、经历和可迁移能力依据。
3. 每次都联网检索目标公司和岗位，不依赖记忆。优先使用公司官网、官方产品页、官方招聘页和岗位页面；必要时用近期可靠来源交叉核对。
4. 公司存在同名歧义，或缺少岗位名称而无法形成针对性回答时，只询问一个必要问题后暂停生成。
5. 简历不存在或无法读取时，明确说明无法个性化，不得虚构经历、技能或兴趣。

不要复制或输出简历中的联系方式、地址等无关个人信息，也不要把简历内容保存到 skill 目录。

## 工作流

1. 确认公司的准确主体、核心产品或服务、主要客户，以及与目标岗位最相关的业务方向。
2. 从简历中选择一至两个与岗位最相关的真实事实，不罗列全部技术栈。
3. 将公司事实、岗位职责和简历事实对应起来：
   - 公司介绍聚焦“提供什么、服务谁”。
   - 求职动机使用一个具体公司特点，加上岗位匹配和个人动机。
4. 为每条回答提炼 3 至 5 个短关键词，优先使用公司、岗位和简历中的核心概念，方便候选人记忆和展开。
5. 检查公司事实是否有当前网页依据，个人陈述是否能从简历得到支持。
6. 识别回答中的英文缩写、行业术语和公司特有产品名；结合简历判断候选人是否可能陌生，只解释真正影响理解的术语。
7. 严格按规定格式输出，不添加扩展准备、可能追问、反问建议或总结。

## 输出格式

```markdown
1. **公司是做什么的？**
   **回答：** <最多一至两句话>

   **记忆关键词：** <3 至 5 个短关键词，用“｜”分隔>

   **术语注释：**
   - **<术语>**：<用一句通俗的话说明它是什么、解决什么问题>

2. **为什么想来我们公司？**
   **回答：** <最多一至两句话>

   **记忆关键词：** <3 至 5 个短关键词，用“｜”分隔>

   **术语注释：**
   - **<术语>**：<通俗解释>
```

没有需要解释的术语时，省略该项的“术语注释”。公司事实需要引用时，将官网或岗位页面链接放在回答句末，不另设“来源”章节。

## 回答标准

- 使用自然、克制的第一人称口语，答案应能直接说出口。
- 每项的“回答”最多一至两句话；术语注释不计入句数。删除背景铺垫、重复解释和空泛形容词。
- 每项必须有一行“记忆关键词”，包含 3 至 5 个短关键词，使用“｜”分隔；关键词应概括回答主线，不重复整句答案。
- 公司介绍保持客观，不照抄宣传文案。
- 求职动机必须体现该公司的具体特点，避免“平台大、发展好”等通用套话。
- 在术语首次出现的对应问题下解释；每个问题最多解释三个术语，每个术语只写一行。
- 用“它是什么、解决什么问题”的生活化语言解释，不用更多专业词堆叠定义。
- 简历已体现候选人熟悉的 Go、Redis、并发等基础技术默认不解释；行业语境赋予其特殊含义时除外。
- 一个问题需要解释超过三个术语时，先把回答改写得更通俗，而不是继续增加注释。
- 不输出未核实的融资、规模、客户、市场地位或最新业务信息。
- 不在三项之外提供可选内容；术语注释必须放在对应问题内部。

## 注意

未指明岗位时，默认是Go后端开发岗位。
