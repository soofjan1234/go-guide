# 手机 BOSS 搜索与沟通

脚本独立完成：**搜索筛选 → 列表预筛去重 → 读取或复用完整 JD → 规则匹配 → 立即沟通并核对状态。** 疑难岗位标为待核，结束后可集中复查，无需 AI 逐个判断。

脚本运行后直接处理符合条件的新岗位，不再生成预览清单、确认码或定制招呼语。点击“立即沟通”时，BOSS 可能发送已配置的默认招呼；脚本不额外输入文字、不交换附件简历、不修改在线简历，因此不需要 ADBKeyboard。

## 运行

准备 Python 3.10+、PATH 中的 `adb`，手机已允许本电脑调试。保持手机解锁、打开 BOSS，并在搜索页选好深圳。QtScrcpy 可以继续显示画面，但不要与脚本同时输入，也不要同时运行 feedback-reader。

默认使用 uiautomator2 常驻采集。本机已配置独立环境，验证版本为 uiautomator2 3.7.1、adbutils 2.12.0。在仓库根目录先设置解释器：

```powershell
$bossPython = '.\tools\boss_apply_data\runtime\u2-venv\Scripts\python.exe'
```

执行或续跑：

```powershell
& $bossPython -X utf8 -B tools/boss_apply.py run --serial 3140629688000FO --limit 10
```

默认关键词 `go`、城市深圳、月薪 15–25K；默认目标 10 个，单批最多 30 个新岗位沟通。地点直接在 BOSS 搜索页筛选深圳，详情字段仅作兜底核对。必须指定手机序列号，不能默认选取同时连接的其他设备。

中断后使用同一命令续跑。例如目标 10 个、已完成 6 个，重启后只补剩余 4 个。已完成的批次再次运行不会新增沟通；明确开始另一批时加 `--new-batch`：

```powershell
& $bossPython -X utf8 -B tools/boss_apply.py run --serial 3140629688000FO --limit 10 --new-batch
```

`--keyword`、`--city`、`--salary-min`、`--salary-max` 可调整搜索条件。搜索词只支持 ASCII，目标薪资限 10–50K。城市不符且无法确认选择入口时停止，手动选好再运行。

本机薪资筛选档位为 10–20K、20–50K，脚本分两轮读取，再按岗位实际薪资细筛；与 15–25K 有交集即可纳入，例如 18–30K、17–27K。`--pages` 默认为每档最多 8 次翻页，达到上限不表示全量岗位已覆盖。

只查看当前手机页面，不发起沟通：

```powershell
& $bossPython -X utf8 -B tools/boss_apply.py inspect --serial 3140629688000FO
```

## 匹配和去重

先在列表跳过历史已沟通、本地已有尝试、薪资无交集、地点不符、标题明确外包或驻场的岗位。列表明确显示 5–10 年、10 年以上或硕博学历时，提前标为待核，不再打开详情。经验学历标签缺失或有歧义时继续读 JD；标题没写 Go 也继续读。

其余岗位打开详情核对身份，读取完整 JD，再判断 Go、年限、学历、用工方式及已知硬性经验要求：

- 明确外包、驻场、地点或薪资不符、非 Go、岗位关闭、已有沟通记录：跳过。
- JD 未展开、身份字段缺失、用工性质含糊、年限或硬性经验存在疑问：标为 `review`，本轮不沟通。
- 规则匹配且未沟通过：立即点击“立即沟通”。规则匹配不代表已证明岗位完全适合。

公司名称、JD 中的“非外包”“不驻场”“无外包经历”不作为外包证据。K8s 等加分项不直接排除。判断使用本地规则，不调用外部模型分析或上传 JD。

可读取 feedback-reader 的既有历史，支持多个 `results.json` 或包含该文件的目录：

```powershell
& $bossPython -X utf8 -B tools/boss_apply.py run --serial 3140629688000FO --limit 10 --history 'D:\PersonalGrowth\生活领域\求职\feedback-reader\output\vivo-month-2026-09-23_2026-10-22' 'D:\PersonalGrowth\生活领域\求职\feedback-reader\output\vivo-account2-month-2026-09-23_2026-10-22'
```

历史和尝试记录按“公司＋岗位”去重，同岗换招聘人也跳过；同公司不同岗位分别判断。招聘人仍用于点击前后的身份与证据核对。仅统一末尾省略号的显示差异，不把公司前缀当完整公司名匹配。点击前再次检查当前岗位是否已显示“继续沟通”，不能把旧历史当作当前全部状态。

Agent 采用硬关键词过滤：标题或完整 JD 出现 `Agent`（不区分大小写，包括连写）、“智能体”或“智能代理”即跳过。加分项、工具描述和终端 Agent 也不放行，不再依赖章节或职责推断。公司名称字段不参与这项过滤。规则在本地执行，命中原因保存在岗位记录中。

列表与详情公司或岗位身份不符时，保留两边信息，标为待核并从已识别的详情页返回，继续下一条；不把客户公司和猎头机构合并为同一公司，也不发起沟通。未知页面和发送结果不明仍停止整批。

新建 30 个岗位批次时指定目标数量，后续续跑保持相同参数并去掉 `--new-batch`：

```powershell
& $bossPython -X utf8 -B tools/boss_apply.py run --serial 3140629688000FO --limit 30 --pages 30 --new-batch
```

## 沟通状态如何核对

点击前先保存 `contacting` 意图，再点击一次“立即沟通”。以下任一证据成立才记为 `contacted`：

- 相同公司、岗位、招聘人的详情页已显示“继续沟通”。
- 对应招聘人的聊天页中，岗位卡片匹配，并出现开始沟通时间，或本人默认招呼的送达／已读／未读状态。

仅打开聊天输入框不算成功。招聘人、岗位卡片不符，或点击超时后无法核对时，记为 `unknown` 并停止后续岗位；只重读一次，不再点击。`contacted` 不表示附件简历已发送、HR 已读或已经回复。

确认沟通状态后返回列表，继续下一个岗位。聊天已有草稿时保留草稿并停止自动返回，不覆盖用户输入。

## 记录与恢复

输出默认位于 `tools/boss_apply_data/vivo-current/`，已加入 `.gitignore`：

- `results.json`：当前批次目标、已处理岗位、完整 JD、匹配依据及实际结果；每个岗位处理后保存，重启继续使用。
- `results-*.json`：显式创建新批次或迁移旧版报告时保留的归档。
- `journal.jsonl`：累计保存沟通尝试及结果，跨运行去重；旧版已有发送尝试同样阻止重复触发。
- `negative-cache.json`：跨批次复用近期读过的 Agent 或资格不符项，最多保留 1000 条、有效期 6 小时；命中时只跳过或标为待核。
- `evidence/`：当前页面 XML 和展开 JD 时的必要截图。

`contacting`、`unknown` 和已沟通记录都会阻止后续自动重复点击。发生未知结果先查看实际聊天，不要直接删除记录重跑。旧版 `plan.json`、`preview.md` 不再是执行入口。

续跑会先用沟通日志校正数量：日志已确认成功、报告尚未更新的岗位也计入已完成；存在未确认的点击时停止，`--new-batch` 同样不能绕过。更改城市、薪资或目标数量时，必须明确创建新批次。达到翻页上限但未达目标时记录为 `exhausted`，不会误报完成。

同批次已读 JD 会缓存。再次遇到时仍打开详情，只有身份、薪资、地点、年限、学历和当前正文摘要一致，才复用完整 JD；条件变化则重新读取。历史文件路径也随批次保存，续跑无需重复输入。旧版报告先归档，再按本次运行参数新建批次。

跨批次拒绝缓存仅保存身份匹配、JD 完整且已判定 Agent 或资格不符的岗位。账号、筛选条件、规则版本改变，或公司、岗位、招聘人、薪资、地点、经验、学历、列表摘要任一变化，都重新读取；必要字段缺失也不命中。缓存命中不延长有效期，记录原始证据和到期时间。完整 JD 在列表摘要不变时仍可能更新，因此缓存最多推迟 6 小时重读；需要立即重查时可删除此缓存文件，保留沟通日志。

`--account` 是本人指定的本地账号标签，不会自动识别登录账号；换账号时更换标签。`--output` 可调整保存位置，后续运行应复用同一位置，否则不能利用原有沟通日志去重。

完整 JD 展开复用本机 `D:/PersonalGrowth/生活领域/求职/feedback-reader/ocr_text.ps1`，可用 `--ocr-helper` 指定同一辅助程序的其他位置；缺失时仍可读取界面，但未展开 JD 的岗位只标待核。正文底部被滚动容器裁切时先滚动，不做无效 OCR。返回和滚动复用两秒内的页面，沟通前后仍重新读取并核对身份与结果。原反馈采集脚本保持只读用途。

## 常驻采集与等待

每次独立采集及每轮动作后等待开始时，从 Android 主屏读取应用可用宽高和旋转方向；同一等待循环内复用尺寸，旋转时重新读取，循环结束即失效。点击前仍独立重读尺寸和页面。按可用区域裁剪负坐标、底部系统栏及屏幕外节点，不能硬编码屏幕高度。uiautomator2 保留完整节点、深度 50、当前活动窗口，复用原来的岗位与沟通状态解析。

页面就绪轮询窗口为 5 秒，以目标页面、岗位身份和沟通证据判断，并等待连续两帧业务字段和控件位置稳定。岗位身份、JD、薪资、经验学历、按钮位置、筛选选中状态、聊天草稿及沟通证据变化仍会继续等待；活跃状态、装饰头像和无关推荐内容刷新不再阻碍就绪。筛选面板保留全部文字和可操作控件的位置比较，未知页面沿用完整树比较。超时停止，绝不重放点击。“立即沟通”的写前日志和结果核对继续保留。

JD 使用较短滚动手势，减少越过正文后节点被列表回收的情况。只有在返回按钮、竞争力分析模块与沟通按钮同时存在时，才把已观察到的详情底部视为同一岗位页，允许继续滚动读取或返回；此时仍不能跳过完整 JD 和身份核对直接沟通。

搜索词仅通过已确认的 `et_search` 编辑框整段设置，写入后读回；不安装输入法。已观察到的“添加多个求职期望”提示只通过返回关闭，不点击“立即添加”，不修改求职设置。其他未知提示仍停止。

辅助服务在专用端口 19018 运行，脚本正常结束或发生异常时关闭。采集连接或可用显示区域出错时，先关闭本次服务，再改用原 ADB 方式；此次运行不再自动切回。锁屏、验证码和未知应用仍停止流程。需要主动使用旧方式时运行：

```powershell
python -X utf8 -B tools/boss_apply.py run --serial 3140629688000FO --limit 10 --backend adb
```

`results.json` 的 `capture_backend` 记录实际采集方式；`timings` 累计运行、搜索、读取 JD、沟通核对的耗时，单位为秒。`device_metrics` 记录各方式采集次数、采集耗时、OCR、服务启动、就绪轮询、`viewport_queries`（屏幕尺寸查询次数）与降级次数。就绪等待包含其中的采集耗时，这些分项均与流程耗时重叠，不应相加。

锁屏、未知页面、验证码、频率限制或连接失败时保存进度并停止。单设备运行锁防止本脚本并发操作；崩溃遗留锁需确认进程退出、核对沟通日志后处理。退出码 `0` 表示本次流程正常结束，`2` 表示停止或需要处理；实际沟通数量以 `results.json` 为准。

## 验证

```powershell
python -X utf8 -B -m unittest discover -s tools -p test_boss_apply.py
```

测试覆盖列表资格预筛、两类缓存失效、续跑与日志恢复、沟通身份核对、动态坐标裁剪、主屏与虚拟屏区分、轮询尺寸复用及旋转刷新、装饰变化与业务稳定、搜索框整段设置、采集故障只读降级和已知提示的安全关闭。模拟点击通过不等于真机已建立沟通，整批提速效果以实际批次记录为准。

2026-11-06 优化后的同页只读测试：新旧版各 20 次就绪等待，平均 0.988 → 0.920 秒，减少约 7%；尺寸查询 40 → 20 次，业务字段一致、无采集降级。另回放 34 条既有成功沟通证据，核对结果一致。该测试未新增沟通，详见[只读验证报告](boss_apply_data/vivo-current/optimization-readonly-20261106.md)。

随后完成[优化后 30 个岗位实测](boss_apply_data/vivo-current/batch-20261106-140157.md)，完整 JD 和沟通证据均复核通过。主脚本累计 9 分 53 秒，含一次 BOSS 沟通次数提示核验的自然耗时为 12 分 23 秒；按实际沟通次数归一，耗时比上一批减少约 23%。岗位内容和中断情况不同，批次差异不能全部归因于页面等待优化。跨批次拒绝缓存本批命中 0 条，尚无实际命中率证据。
