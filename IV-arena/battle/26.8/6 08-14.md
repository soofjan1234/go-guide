## Go 切片、数组与扩容

**问：** Go 的切片和数组有什么区别？

**答：** 首先切片是可变的、可扩容的，数组是定长的，然后它们的定义以及初始化方式都不一样。
接着就是作为函数参数传递的话，数组是复制整个数组，切片只用复制它的结构，就是一个指针，然后 len 和 capacity，这样就快点。
这也说到它们的底层结构不一样。数组本身就是一个数组，切片有一个指针指向一个数组，然后有长度以及容量。

**问：** 还有吗？append 切片的时候会有什么行为？

**答：** 切片进行扩容的话，就是大于 capacity。首先会看这个 capacity 乘以二是否小于这个 len，如果小于的话，我们就直接用这个 len 来作为容量。
如果大于的话，我们要继续看它是否小于 256。如果小于的话，我们就直接双倍扩容；如果大于的话，我们就平滑过渡到 1.25 倍扩容，直到它大于新长度。
然后我们算出来的也是一个大致的容量。Go 进行内存分配的时候是按块来进行分配的，比如说 8、16、32，得到的是一个 30，它会给你一个 32 的内存块，然后就是开辟新空间进行迁移了。

## Go Map、Channel 与 GMP

**问：** Go 的 Map 给我讲一下。

**答：** Map 在 1.24 之后就是一个 Swiss Table 的结构了，是由 table 来组成的。Swiss Table 的结构是一个连续的组，每个组有八或者十六个槽位，每个槽位也有 metadata 与之对应。
我们给到一个哈希值，前 57 位会在这个组里定位到哪个组、哪个位置，后 7 位会加上一个标志位，放到 metadata 里面。
然后 Go 里面的 Map 做了一些改进，它有个指针，可能指向多个 Map、多个 Swiss Table。如果元素特别少，小于八个的话，它指向一个 group 就够了。
这个 Swiss Table 还有一个优势，就是 SIMD 能够一次性地比对多个数据。利用 CPU 的计算器，能够比对多个 metadata，这样查找的速度就会更快。

**问：** Go 的 Channel 呢？

**答：** Channel 有一个缓冲区，是个数组，然后有两个指针，一个是发送指针和接收指针，就是表示在哪里发送、哪里接收。
然后还有个锁，每次操作前要加锁。接着还有一个 closed，表示是否关闭；还有这个 count，代表有多少个元素在这个环形缓冲区里面。
发送的话，首先看这个 Channel 有没有被关闭，如果关闭的话就会 panic。然后再看有没有接收者在这里等待，如果有的话我们就直接给他。
没有接收者的话，我们就看这个缓冲区域有没有位置可以放；有得放我们就放里面。没有的话，再一起去看有没有设置非阻塞；有的话我们就直接返回，没有的话就只能进入阻塞了。

**问：** Go 的 GMP 能讲一下吗？

**答：** G 是协程，然后它有执行现场以及执行状态。
M 是线程，它有绑定的 P、即将要绑定的 P、进入系统调用前绑定的 P，还有正在运行的 G。
P 是处理器，它包含一个长度为 256 的本地队列，还有一些缓存，mcache、pcache。
它们之间的关系就是每个 M 要绑定一个 P 才能够运行 G。还有一个 schedt，它是一个全局调度中心，持有锁、全局队列，还有一些可复用的、空闲的 M、P 列表。一般本地找不到的话，就会去全局找这个 G。

然后我还了解它的调度以及 findRunnable 的流程。它的调度首先会进入 `rt0_go` 汇编文件，然后会进行 `schedinit`，先准备好内存、GC、P。
然后会创建 G，就是使用 `newproc` 来复用或者创建一个 G，并且让它入队。
第三步就是进行线程的 start，然后正式进入这个循环，会先去 `findRunnable`，找到可运行的 G 进行运行。
中途可能会有一些阻塞或者系统调用导致阻塞，那么它就会周而复始地寻找新的可运行的 G 来进行运行。

## Go 内存管理、逃逸、泄漏与 GC

**问：** 你能给我讲一下 Go 的内存管理吗？

**答：** 内存管理的话，如果是空的话，就是放到这个 base 里面。（转写不清）
如果是小对象的话，应该也是放到这个 mcache 里面，然后等分满了才进行申请。再大一点的话就放到这个 mcache 里面，这里是每个 P 都随身携带的对象缓存。
再大一点的，我们可能就要去 mcentral 拿。mcentral 就有我刚才说的内存块分配大小，比如说 8、16、32 这样子。
mcentral 也没有的话，就是 mheap 进行直接划分。
然后它有什么 pageAlloc 和 fixAlloc，那些就是管理类的东西了：一个是有哪些连续可划分的空闲区域，还有一个就是 span 对应的页以及分配这些东西的。（未答完整）

**问：** Go 的内存逃逸和内存泄漏怎么区分？

**答：** 内存逃逸的话，是编译器认为这个变量可能超出栈的生命周期，就被逃逸到堆上。
可能的原因就是闭包，或者函数返回了指针，或者向通道、Map、切片加入指针或者含有指针变量的值，反射吧。
进行查看的话，就是 `-gcflags=-m`，可以查看比如说 `moved to heap`，有没有进行逃逸。

内存泄漏的话，就是内存越积越多，可能导致 OOM。
可能的原因就是 Map 和缓存的指针不减，还有一些连接和文件没有关闭，或者 Goroutine 泄漏。
还有一些错误地在循环里面使用 time.Ticker，以及订阅的回调没有注销。
可以通过 pprof 来查看。首先进行复现或者压测这些场景，用 pprof 看它的累积热点函数。接着还可以通过 `GODEBUG=gctrace=1` 来进行查看。

**问：** 你能讲讲 Go 的 GC 吗？

**答：** GC 首先是它的触发时机。一个就是定时的，每 2 分钟一次；第二个是阈值，GOGC 100，就是堆里面的对象翻倍之后会触发一次；第三个就是手动触发。
它的流程分为四步。第一步是停止世界来找根对象；第二步是并发标记，来标记哪些是需要清理的；第三步是停止世界，进行写屏障缓冲区的清空，最后确认需要清理的；第四步就是并发清理。

白、灰、黑分别是用位图和队列来表示的。位图 0 和不在队列就是白；灰是位图 1 以及在队列；黑是位图 1 以及不在队列。
首先所有的对象都在白里面，然后我们遍历根对象，遍历到的就加入灰里面。
第二步就是遍历灰里面的对象，首先从灰里面提取一个对象来遍历，它能够遍历到的所有对象加入灰里面，然后它本身遍历完了之后就加到黑了。
接着周而复始地遍历灰，直到灰没有了，剩下白的就是需要清理的。大概就是这么多。

**问：** 有什么问题呢？

**答：** 可能会有一个错误清理的问题。
比如说有黑、灰、白三个角色，现在灰是指向白的，本来我们要把这个白加入灰，但是这个时候灰不指向白了，而是由黑来指向白。
这个时候我们不会去遍历黑的对象，所以这个白虽然被指向了，但是没有灰指向它，就可能被错误地清理。
所以写屏障就是为了防止这种情况，它就是将该对象之前引用的对象以及后面引用的这个新对象，都加入到里面，防止这个现象。

## MySQL 事务、日志与 MVCC

**问：** MySQL 的事务有哪些特点？

**答：** 事务的特点主要是 ACID。A 是原子性，事务要么完成，要么不完成；I 是隔离性，就是事务之间互不干扰；D 是持久性，就是事务发生的改变永久生效；C 是一致性，事务前后数据保持一致。
然后就是由 A、I、D 共同促成 C 的成功吧。

**问：** 它不同的特点是怎么实现的呢？

**答：** A 的话，事务要么完成、要么不完成，我们可以使用 undo log 来进行回退。
事务之间的隔离主要是通过 MVCC 以及锁来保证。事务发生的变更永久有效，也是靠 redo log 在崩溃后进行恢复的。

undo log 方便回退，它有版本链。新修改数据之后，旧的数据会放到 undo log 里面，有 row pointer 进行连续的指向，我们可以进行回退。
MVCC 是在不加锁或者少加锁的情况下，保证高并发的读写。
redo log 用于崩溃后的恢复。它是什么表、什么页、什么偏移，写了、修改了什么，然后它也是循环写的这么个东西。
它还有 checkpoint，我们只用恢复 checkpoint 之后的，因为 checkpoint 之前的都已经同步到磁盘里面了。

**问：** 还有吗？

**答：** MVCC 主要跟 undo log 和 Read View 来进行实现。
undo log 刚才说的是方便回退，Read View 告诉你当前事务哪些数据能读、哪些不能读。
它有几个角色：事务开始的时候正在活跃的 ID 集合、下一个要分配的事务 ID，还有最老的一个活跃事务 ID。
每当有个数据过来的时候，我们会看当前数据的修改事务 ID 是多少，接着看它是否在活跃事务 ID 里面。如果是的话，我们就不能看这个数据。
如果它比最老的活跃事务 ID 小，就可以查看；如果它比下一个要分配的事务 ID还大，就不能查看。

## Redis 缓存问题与布隆过滤器

**问：** Redis 的缓存穿透、缓存击穿和缓存雪崩有什么区别？

**答：** 缓存穿透是多个不存在的 Key 去访问这个服务，导致 Redis 没有、数据库也没有，导致数据库压力很大。
解决方法第一个是缓存无效的 Key，第二个可能是限流，第三个是布隆过滤器，它能够决定这个东西一定不在。

**问：** 布隆过滤器是怎么实现的呢？

**答：** 布隆过滤器有多个哈希函数以及一个位数组来实现。
首先新增一个值时，我们会让不同的哈希函数根据这个值生成不同的哈希值，接着这些哈希值都映射到位数组对应的位上。
接着要看这个 Key 存不存在时，我们也做同样的操作，生成不同的哈希值，然后看位数组对应的位。如果有 0，就代表不存在；如果全为 1，就代表可能存在。
它的缺点好像就是删除了这个 Key，也不能够进行布隆过滤器相应的删除，因为也有可能别的 Key 占用了相同的位，所以我们可能要定期重建。

缓存击穿是有个热点数据突然过期了，导致请求都打到数据库里面。所以可以进行提前预热、永不过期，又或者 Go 里面有个 singleflight，能够将多个相同的请求合并成一个。
缓存雪崩是有多个热点 Key 同时失效了。针对 Redis 服务不可用的情况，我们可以开集群；如果是热点缓存的问题，可以设置不同的过期时间以及提前预热。大概是这样子。

## MySQL 与 Redis 数据一致性

**问：** MySQL 和 Redis 都存的时候，数据一致性怎么保证？

**答：** 最常用的是旁路缓存。读的时候先读 Redis，没有的话再读数据库，然后回填 Redis。进行修改的时候，我们先更新数据库，再删除缓存吧。

如果是先删除缓存、再更新数据库，这个时候如果 A 这么操作，它先删除缓存再更新数据库；B 在中间进行数据库读取，就会进行缓存回填。这样就会导致缓存还是旧的，但是数据库已经是新的了。

然后如果是先更新数据库再更新缓存，不管是先更新哪个都有可能出现问题。
比如说 A 要更新数据库再更新缓存，B 也是想这么做。可能更新数据库 A，然后更新数据库 B，接着更新缓存 B，再更新缓存 A。这样数据库是 B，缓存是 A，也会导致数据不一致。

## 计算机网络、DNS 与浏览器访问流程

**问：** 网络上的话，计算机网络有哪几层？

**答：** 我了解的是应用层、传输层、网络层、数据链路层和物理层。
应用层主要是 HTTP 或者 HTTPS、SMTP 相关的邮件协议；传输层和网络层分别是 TCP 以及 IP；再下一层是数据链路层，就是 MAC；再到物理层，可能就是光纤和电的。

**问：** 在浏览器输入一个网址的时候，有哪些流程？

**答：** 首先会查找 IP 地址，是通过 DNS。先看本地有没有相关映射，然后交给递归解析器去查找 IP 地址。
它会去根、TLD 还有权威服务器，得到最终的 IP 地址。
返回过来之后，第二步就是三次握手以及 TLS。之后第三步进行封装，比如 TCP 的包、IP 的包、MAC 帧，都是一层一层封装。
下一步就是下一跳，不断地重写 MAC 地址，但是 IP 是不变的。
最后那边的服务器解析、得到请求，处理后得到响应发送出去。我们这边再进行对应的解析，比如 HTML、CSS 相关资源。大概是这样子。

## HTTP、HTTPS、密钥协商与证书

**问：** HTTP 和 HTTPS 有什么区别？

**答：** HTTPS 是 HTTP 加 TLS，然后它有了一个加密过程。
它们用的是混合加密。比如 A 要跟 B 进行 HTTPS 通信，首先各自生成各自的公私钥，然后让公钥进行交换，接着用自己的私钥和对方的公钥生成共同的秘密，再派生出密钥。
如果要发送请求，我们就用这个密钥进行加密，B 这边用密钥进行解密，是这样子。

还有个中间人攻击的问题。可能有一个 C，把自己的公钥给 A 和 B，然后截取 A 和 B 之间的公钥。这样 C 就能够偷取他们的请求内容。
解决方法是使用证书。证书包含基本信息、公钥还有数字签名。
生成数字签名，应该是首先把基本信息给哈希函数，得到一个哈希值，哈希值又用私钥进行加密，得到数字签名。
我们拿到这些东西之后，用原始信息通过哈希函数得到相同的哈希值，接着将数字签名用公钥解密得到哈希值，对比这两个哈希值是否不同，就能够验证对方的身份。
