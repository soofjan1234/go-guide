## MySQL

**问：** 数据库用过，有些时候是用这个 MySQL 以及 SQLite。可以简单说一下 MySQL 里面的 Join 类型有哪些？
**答：** Join 的话好像是 inner join、left join、right join 和这个 outer join。
那 inner join 呢，它就是只有这个关联起来的那行。
那 left join 呢，它就是左边的一个表的全部数据呢都去到这个最后的一个结果表之中。
right join 的话就是只有右边才有，然后 outer 的话应该是全部都有的吧。

**问：** 可以简单说一下数据库事务的四个特性吗？
**答：** 四个特性的话是 ACID。A 是原子性，事务要么完成要么不完成。
第二个呢是这个 I，它是隔离性，事务之间呢互不干扰。
D 的话是持久性，就是数据这个变更永久有效。
那 I 的话呢它就是一个一致性，前后呢保持一致。（A/C/I/D 对应关系说混）
A 的话是靠这个 undo log 来进行一个实现的，能够进行回退。
然后 I 的话，隔离性呢它是靠这个 MVCC 以及锁来实现。
D 的话，持久性的话就是通过 redo log。
那就由这个 ACD 来保证这个 I 的一个实现吧。

## Redis

**问：** 数据库那个 Redis 是有使用过吗？可以简单说一下 Redis 里面的缓存击穿、缓存穿透以及缓存雪崩。
**答：** 有使用过的。缓存穿透的话，那就在一个商城里面了。你一直用这个不存在的商品 key 去访问，它就一下全都打到了这个数据库里面。
那么可以解决的方法呢，有这个缓存无效的 key 及限流。还有就是做这个布隆过滤器，才能够保证这些数据呢它一定不存在。
然后呢就是这个缓存击穿，它的话就是某个热点 key 呢失效了。那我们可以进行一个提前预热以及永不过期。那 Go 里面呢还有 singleflight，那就是能够将多个相同的 key 请求呢都弄成一个。
然后缓存雪崩的话，就是有多个热点 key 都同时失效了。那么对于这个 Redis 服务不可用的情况下呢，我们可以做这个集群。
然后对于缓存的话，我们可以做这个分批过期或者是永不过期吧。

## 消息队列 / RabbitMQ

**问：** 消息队列你熟悉有吗？可以简单说一下 RabbitMQ 是怎么确保消息不丢失。
**答：** 有使用过 RabbitMQ。消息不丢失的话，那么从这个生产者开始呢，他会开启这个 publisher confirm，就是保证这个消息呢都到了这个消息队列里面，然后还要开启那个 mandatory 以及处理这个请求回调。
这是为了保证这个消息还要投递到这个 queue 里面。
然后说到这个消息队列的话，exchange 和 queue 的话要开启这个 durable，然后呢 message 要开启 persistent 来做这个持久化。
然后消费者的话呢就是开启这个手动的 ack，你处理完了请求才返回这个 ack。

## 线上排查

**问：** 如果一个线上网页加载很慢，你会怎么调查和解决呢？
**答：** 加载慢的话，首先要看这个是单个用户还是多个用户以及它的一个出现的一个时间段，还有单个用户。
然后呢这些用户他们所在的地区是有没有共同的特性啊，比如说都在某个区域，那么可能是这个区域的网络有问题，又或者是这个 CDN 资源或缓存没有打到。
然后的话可以去看那个 F12，去看这个网页加载的个情况，能够看到各个链路的一个情况。
如果是前端资源多的话，会不会是 404 又或者是图片加载过多？
如果是后端的话，数据库方面，会不会一下查询了太多导致了这个慢查询，然后 Redis 会不会有这个热点 key 的问题吧。
然后 Go 如果是 Go 服务的话，还可以通过 pprof 来去看它的一个 CPU 时间。

**问：** 你这边之前有没有遇到特别难的一个问题，最终你是怎么调查和解决的？
**答：** 有遇到这个文档中心，出现了这个执行异常的问题。然后呢，我去询问这个用户，他做了什么操作，就是导入了一大堆的比较长的一个 txt 的文档。
然后我就是在自己的测试机上进行复现。接着呢去看这个日志，发现没有打印，也没有这个 panic 输出。
接着呢我就怀疑是资源受限的问题，就是通过 top 命令去看了，发现这个文档中心呢它在解析文档的时候呢，内存占用率会飙升。
然后的话就通过这个 pprof 来去看它的一个瓶颈是在建立 Bleve 这个搜索引擎建立索引的一个阶段。
接着呢我就去看了这个 Bleve 的源码，那么给到了几个方案，就是第一个是他的一个配置。比如说只让这个 title 和 content 来建立倒排索引，其他的都不建倒排。
第二个呢是由于配置 `_all` 改为 false 来降低它的一个索引体积。
第三个是分块，1MB 一块来降低它的一个索引峰值。
第四个是批量提交，就是优化它的一个吞吐。
然后最后就是成功的降低了这个内存占用率。
