# 项目面试常问问题

根据 `IV-arena/battle` 中 26.2—26.10 的面试记录归纳，合并相近问法，排除纯基础题、候选人反问和明显的预测题。本次检索覆盖 61 份 txt 和 39 份其他 Markdown，其中包含同场转写与复盘，文件数不等于面试场数，以下不作精确频次排名。

每个主要项目准备一条回答线：**为什么做 → 我负责什么 → 怎么运行 → 为什么这样选 → 难点与异常 → 怎样证明结果。**

## 1. 项目背景、个人职责与贡献

- 这个项目解决什么问题，用户怎么使用？
- 整体有哪些模块，你负责哪些，与谁交互？
- 是你从零搭建，还是接手维护？
- 哪些方案由你提出，哪些由算法团队、第三方或上级提供？
- 项目是否上线，有多少用户、数据和请求？

考察重点：你做的究竟是什么，以及哪些成果能归到你身上。

## 2. 整体架构与完整业务流程

- 介绍项目架构，从请求进入到结果返回完整讲一遍。
- 手机、云端、NAS、穿透端分别负责什么？
- 文件从发现、解析到入库、检索，经过哪些步骤？
- AI 相册的模型推理、结果存储和前端展示怎样串起来？
- 服务之间通过什么方式通信，分别部署在哪里？

考察重点：能否把系统讲成一条完整链路，而非几个技术名词。

## 3. 技术选型与方案取舍

- 为什么选 Bleve，不选 ES、Meilisearch？
- 为什么从 fsnotify 改成 BFS 加队列？
- 为什么选 NSQ，其他消息队列能不能用？
- 为什么选 DBSCAN，而不是 K-Means？
- 为什么并行计算、串行落库？为什么选 WaitGroup？
- 做过实际对比测试，还是只看过文档？

考察重点：知道约束、备选方案和代价，能够说明为什么这样选。

## 4. 核心实现与底层原理

- 分块索引如何组织，主文档、子文档怎样关联，搜索结果怎样聚合？
- `_all` 字段有什么用，为什么关闭后能减少占用？
- 分词器为什么用 Trie，怎样减少 CPU 开销？
- Worker、Channel、WaitGroup 怎样配合，结果怎样批量写入？
- fsnotify 为什么消耗资源、为什么会漏事件？
- NAT 打洞、信令交换、TLS 和应用层加密分别怎样工作？
- 模糊检测、相似图、人脸聚类具体怎么实现？

考察重点：不仅知道方案名称，还理解完整执行流程和代码细节。

## 5. 性能优化与效果验证

- 内存降低 70%／76%，优化前后分别是多少？
- 怎么发现瓶颈，用什么工具和指标定位？
- 吞吐提升 1.6 倍、延迟降低 50%，怎么测出来的？
- 测试文件多大、多少份，设备配置是什么？
- 分块为什么选这个大小，批量为什么选 100？
- 有没有测试更大、更小、多个并发写入的方案？
- 人脸准确率依据什么测试集和样本量？
- 优化内存后，耗时、实时性或识别效果有没有变差？

考察重点：能否讲清实验和实验结果，数据是否可信，以及优化带来的取舍。上述百分比是面试中被追问的简历表述，不代表本文重新验证了效果。

## 6. 异常处理、可靠性与数据一致性

- 服务重启后，队列中的任务怎么办？
- 文件新增、修改、删除，数据库怎样跟真实文件保持一致？
- 消息怎么保证不丢、不重复、顺序正确？
- 业务处理成功但请求超时，再重试会不会重复执行？
- 事务和幂等怎么做？
- 打洞失败怎么办，切换网络后怎样恢复？
- 大文件解析失败、异常输入，是否影响其他任务？

考察重点：正常流程之外，失败、取消、重启时怎样处理任务和保持一致性；区分实际实现和待补充方案。

## 7. 线上故障、部署与运维

- 遇到过最严重、最棘手的线上问题是什么？
- 用户反馈慢、服务异常或内存持续上涨，如何排查？
- 使用 Gin 时有没有遇到实际问题？
- 服务怎样部署、升级和管理？
- 有没有监控、日志、用户反馈指标？
- 故障恢复后怎样复盘，避免再次发生？
- Docker、K8s 是生产实际使用，还是个人学习？

考察重点：是否实际承担过交付和运行责任；没有经历的事故不编造，个人实验不等同于生产经验。

## 8. 需求推进、团队协作与 AI 开发

- 接到一个需求，怎样推进到上线？
- 有没有需求、技术和接口评审？
- 与前端、移动端怎样对齐、联调？
- 需求变更、方案冲突或不合理要求，怎样处理？
- 有没有主动发现问题并推动改进？
- AI 在哪些阶段用得最多，举一个具体例子。
- 怎样给 AI 项目上下文，审查代码、设计测试和验收？
- 哪些判断由你完成，AI 出错时你如何发现？

考察重点：能否独立推进工作，并对交付结果负责。

## 各项目的准备重点

| 项目 | 反复出现的追问主线 |
| --- | --- |
| 文档中心 | 搜索引擎选型 → 内存定位 → 分块与分词实现 → 搜索聚合 → 优化验证 |
| 文件索引同步器 | fsnotify 问题 → BFS／队列 → 增量同步 → 重启恢复 → 实时性取舍 |
| AI 相册 | 算法与模型来源 → 检测和聚类原理 → Worker 与落库 → 准确率和性能测试 |
| 云端／穿透 | 多端完整链路 → NAT 与失败中转 → 身份校验及加密 → 消息队列可靠性 |
| MediaAI | 职责边界 → 调度与模块交互 → 为什么这样设计 → 有哪些改进空间 |
| 个人项目 | 是否实际实现、跑通和部署 → 与公司项目的经验边界 → 具体技术细节 |
