| **P0** | **项目指标与个人贡献** | 2～9 月反复被问内存下降比例、QPS、文件规模、选型依据；到 9 月仍有起止数值答不出的情况。 | 为每个简历数字写清**原值、现值、测试环境、数据集、测量方法、代价**。同时标明哪些是你实现的，哪些来自 SDK、算法组或其他同事。无法核实的数字先不要口述。 |
| **P0** | **项目主链路与失败路径** | NSQ、Bleve、文件同步、NAT 穿透、相册任务反复被连续追问；常在“失败后怎么办、重启后怎么办、如何保证一致”处断开。 | 每个主项目准备一页：**背景 → 数据流 → 我的实现 → 异常与恢复 → 结果**。优先完成文档中心和文件同步，再处理云端穿透与相册任务。 |
| **P0** | **现场排障的验证步骤** | 慢查询、OOM、线上少量用户失败、发布后 502、RSS 上涨等场景持续出现。列可能原因之后，常缺下一步如何证实。 | 固定回答顺序：**确认范围和时间 → 看指标与近期变更 → 分层定位 → 提出假设并验证 → 止血与复盘**。用真实项目各练一遍。 |
| **P1** | **Go 知识的代码推演能力** | GMP、Channel、Slice、Map、GC 已比早期进步，但一换成代码或阻塞场景，仍可能答偏。 | 少背结构，多手推：Slice 共享数组与 `append`、Channel 关闭与阻塞、文件 IO 对 GMP 的影响、跨 Goroutine 的 `recover`、GC 写屏障。每题用小程序验证预测。 |
| **P1** | **数据库、缓存、MQ 的保证边界** | MySQL 日志与索引、缓存一致性、消息可靠性和三种 MQ 的取舍多次被追问。 | 每题按**适用场景 → 实现机制 → 失败窗口 → 代价**回答。重点练“数据库提交后消息没发出”“更新库后删缓存失败”“用了索引仍然慢”。 |
| **P1** | **网络与安全的分层解释** | NAT、STUN/TURN、TCP、TLS、应用层加密贯穿多个月；9 月网络超时分段排查仍未答完整。 | 画出一次远程访问 NAS 的链路，分别说清 **DNS、TCP、TLS、信令、打洞、业务请求**的作用和各阶段失败如何定位。 |
| **P2** | **目标岗位的扩展知识** | 8～9 月出现 Agent、SRE、K8s、gRPC 等新方向，缺口与投递岗位相关。 | 按岗位准备，不平均用力。投 Agent 就优先上下文压缩、摘要校验与原文回查；投 SRE 就优先发布、探针、指标和故障处置。 |

**建议复习顺序：**先整理简历数字和两个主项目的一页纸，再做 3 个线上排障案例；完成这些后，集中练 Go 代码推演和中间件失败场景。每次练习都让别人沿着“为什么、怎么验证、失败怎么办”继续追问，直到答案不依赖背稿也能讲清楚。
